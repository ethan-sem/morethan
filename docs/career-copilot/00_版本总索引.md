## 1. 版本决策

项目从即日起拆分为两个互不混用的版本：

### A. 纯前端 MVP 版——当前唯一执行版本

目标是尽快形成可以上线、可以真实使用、无需账号和服务器运维的网页产品。

- 无账号、注册、登录；
- 无业务后端和数据库；
- 不上传或长期保存用户简历；
- PDF/DOCX 在浏览器本地解析；
- 默认使用浏览器本地规则完成基础诊断；
- 公司与岗位知识以经过审核的静态 JSON 随网站发布；
- 可选“用户自备模型密钥”实验模式，但不保存密钥，不内置 MoreThan 的商业 API 密钥；
- 报告可在本地查看、复制和导出；
- 现阶段功能完整免费。

### B. 长远开发版——冻结备用版本

只有用户以后明确提出“恢复长期版本”“做账号/后端/数据库”等要求时，才重新启用。

包含：

- 账号、匿名会话认领和跨设备档案；
- 后端 API、数据库、对象存储；
- 服务端模型调用；
- 实时外部岗位数据和来源适配器；
- 顾问/运营后台；
- 报告历史版本、持续行动和投递反馈；
- 完整安全、审计、删除编排与灰度体系。

长期版索引见：[长远开发版说明](./长期开发版/README.md)。原有 `00_总领文档.md` 至 `10_CODEX开发任务清单.md` 已统一标记为长期或共享参考，不得用于当前 MVP 排期。

## 2. 不能同时满足的组合

以下三项不能同时成立：

1. 纯前端、没有任何后端；
2. 网站内置由 MoreThan 付费的模型 API 密钥；
3. 密钥不被访客提取和盗用。

因此 MVP 不会把 MoreThan 的模型密钥写进 JavaScript。默认可用能力来自本地解析和规则引擎；如以后需要统一的大模型深度分析，必须进入长远开发版，至少增加一个最小安全代理服务。

## 3. 当前开发原则

1. 所有新任务只写入 MVP 任务清单。
2. 不实现账号、登录、数据库或服务端保存。
3. 不因追求“AI 感”而内置不安全的密钥。
4. 简历正文默认只存在于用户浏览器内存中。
5. 每项 MVP 能力必须在无账号、无服务器状态下独立工作。
6. 长期文档可以被参考，但不能自动恢复其范围。
