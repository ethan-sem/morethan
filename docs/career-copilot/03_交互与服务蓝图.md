# 交互与服务蓝图

> 版本归属：长期开发版（已冻结）  
> 当前纯前端交互范围见 [MVP 交互与报告设计](./MVP前端版/03_MVP交互与报告设计.md)。

## 1. 体验目标

产品体验应让用户感到“被认真分析”，而不是“被机器审判”。核心节奏是：先建立安全感，再确认事实；先给结论，再逐层展开；先给可执行动作，再承接人工服务。

## 2. 信息架构

```text
智能求职助手
├─ 开始诊断
│  ├─ 隐私与能力说明
│  ├─ 上传/粘贴简历
│  ├─ 事实确认
│  ├─ 目标与约束
│  └─ 智能追问
├─ 我的诊断
│  ├─ 30 秒结论
│  ├─ 背景画像
│  ├─ 优势与短板
│  ├─ 方向建议
│  ├─ 公司岗位池
│  └─ 行动计划
├─ 对话追问
├─ 投递与行动（P1）
├─ 真人复核
└─ 数据与设置
```

## 3. 首次体验分屏

### 屏 1：价值与边界

- 标题建议：`先看清位置，再决定怎么走`
- 说明：上传简历并告诉我们目标，AI 将给出证据化诊断、公司岗位分层和行动计划。
- 辅助信息：约 8–10 分钟；支持 PDF/DOCX；可随时删除。
- 主 CTA：`开始诊断`
- 次 CTA：`先看示例报告`
- 固定提示：`AI 生成建议，不构成录用保证。`

### 屏 2：材料提交

上传区之外，给用户三个明确选择：

1. 上传现有简历；
2. 粘贴文本；
3. 暂无简历，按步骤填写经历。

上传区旁以短文案提示删除身份证号、详细住址、银行卡、健康信息等无关敏感内容。系统识别后再次提示，并默认从分析副本中遮盖。

### 屏 3：事实确认

以时间线和经历卡呈现，而不是大段 OCR 文本。每条事实显示：

- 原文定位；
- 结构化结果；
- 置信度；
- `正确`、`修改`、`不参与分析`。

页面底部提示：“我们只基于你确认的事实形成强结论。”

### 屏 4：目标与约束

采用卡片与排序交互：主投方向、备选方向、城市、入职时间、必须条件、排除项。允许用户选择“请先帮我判断方向”。

### 屏 5：追问

一次只问一个高价值问题，并解释目的。例如：

> 你提到“负责用户增长”。为了判断这段经历对增长产品岗位的价值，我需要知道：你负责了哪一步，指标前后变化如何？

显示进度但不承诺固定题数，如“还需补充约 3 个关键信息”。

### 屏 6：生成过程

展示真实阶段：整理证据、匹配岗位、校准公司池、生成行动计划。不得用虚假“正在搜索 10,000 家公司”动画。超过 30 秒可离开页面并在完成后通知。

## 4. 报告页结构

### 4.1 首屏：30 秒结论

首屏只显示：

- 当前定位：一句话；
- 最强证据：一项；
- 最大阻碍：一项；
- 第一优先动作：一项；
- 报告置信度与主要缺失信息；
- `查看完整诊断`、`纠正事实`、`请顾问复核`。

### 4.2 背景画像

用时间线、证据标签和“已确认/待确认”状态展示。避免生成带人格色彩的标签，如“内向”“缺乏野心”。

### 4.3 优势与短板

卡片固定四段：结论、证据、影响、行动。事实引用可点击回到简历原文。

短板标题使用中性、具体语言：

- 推荐：`缺少可验证的业务结果`
- 不推荐：`经历很水`
- 推荐：`目标岗位跨度较大，材料难以同时兼顾`
- 不推荐：`职业规划混乱`

### 4.4 方向对比

以对比表呈现主投和备选方向，维度仅保留：已有证据、主要差距、准备成本、机会窗口、建议结论。最多比较 4 个方向。

### 4.5 公司岗位池

默认展示四层泳道。每张卡必须同时出现公司与岗位族，并显示：理由、风险、核验时间、状态。层级旁固定解释“这是相对投递组合，不是录取概率”。

支持筛选：城市、行业、公司类型、岗位、是否已核验在招。排除后即时重算，记录用户偏好。

### 4.6 行动计划

先显示未来 7 天，30 天和长期计划折叠。任务卡包含：

- 为什么现在做；
- 预计用时；
- 交付物；
- 完成标准；
- `完成`、`受阻`、`不适用`。

## 5. 对话设计

### 5.1 对话可以做

- 解释某项判断；
- 询问“为什么这家公司是冲刺层”；
- 粘贴 JD 后重新匹配；
- 比较两个岗位方向；
- 将建议拆成更小任务；
- 补充新经历并申请更新报告。

### 5.2 对话不能静默做

- 修改用户确认的事实；
- 将聊天中的情绪表达当作长期人格标签；
- 把敏感信息写入画像；
- 将假设表述为公司真实招聘事实；
- 因用户拒绝购买服务而降低回答质量。

### 5.3 回复格式

复杂问题优先采用：`直接结论 → 判断依据 → 不确定性 → 下一步`。简单问题直接回答，不机械套模板。

## 6. 关键状态

| 状态 | 用户看到什么 | 系统动作 |
|---|---|---|
| 解析失败 | 失败原因与三种修复方式 | 不保存不可用文件或按策略及时清理 |
| 信息不足 | 初步判断与最关键的缺失项 | 禁止生成完整公司分层 |
| 外部数据过期 | 条目标“待核验” | 降级为目标池，不声称在招 |
| 模型超时 | 已保存进度和预计处理方式 | 可重试，不重复计费 |
| 用户纠错 | 受影响结论列表 | 局部重算并保留版本 |
| 高风险请求 | 清晰拒绝与合规替代方案 | 记录风险类别，必要时转人工 |
| 删除完成 | 删除范围和完成时间 | 保留最小合规审计记录 |

## 7. 人机协作服务蓝图

| 阶段 | 用户前台 | AI/系统 | 顾问/运营后台 |
|---|---|---|---|
| 提交 | 上传、确认授权 | 脱敏、解析、置信度标记 | 仅异常时介入 |
| 补充 | 回答关键追问 | 选择高信息增益问题 | 可查看用户主动求助项 |
| 诊断 | 阅读与纠错 | 生成、引用、校验 | 抽检高风险报告 |
| 复核 | 预约并授权共享 | 生成顾问交接包 | 聚焦争议和高价值判断 |
| 行动 | 完成任务、反馈 | 调整优先级、提醒 | 陪跑服务持续跟进 |
| 复盘 | 提交投递结果 | 更新层级和建议 | 汇总共性问题，维护知识库 |

## 8. 视觉与品牌建议

延续现有 MoreThan 的高端咨询机构基调，使用“决策台”而非“娱乐化测评”视觉：

- 证据卡、路径、层级和进度作为主要视觉语言；
- 重要结论留白充足，避免满屏仪表盘；
- 不使用红色大叉、失败等级、人格雷达图制造焦虑；
- AI 使用低调但持续的身份标记；
- 公司 Logo 仅在授权和品牌规范允许时使用；
- 报告导出应适合用户自行保存，不默认包含完整手机号、邮箱等敏感字段。

## 9. 通知策略

只在以下情况通知：报告完成、用户设置的行动到期、公司条目需重新核验、顾问回复、数据保留期将结束。默认不发送高频“你落后了”式促活。

## 10. 可访问性与包容性

- 关键流程可键盘完成；
- 解析与层级状态同时用文字和图形表达；
- 允许较长姓名、海外学校、非线性经历和空档期；
- 不把空档期自动解释为负面；
- 支持用户声明姓名读法和称谓，但不将其用于岗位评分；
- 对明显焦虑表达先稳定情绪、缩小任务，不强化灾难化叙事。
