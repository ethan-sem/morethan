# 技术、数据与合规方案

> 版本归属：长期开发版（已冻结）  
> 本文件涉及服务端、账号和云端数据治理。当前纯前端架构以 [MVP 技术与数据方案](./MVP前端版/02_MVP技术与数据方案.md) 为准。

## 1. 方案目标

在支持简历深度分析的同时，确保最少采集、目的限定、权限隔离、可删除、可追溯和供应商可控。本文是产品与工程基线，不替代正式法律意见或上线前的个人信息保护影响评估。

## 2. 建议架构

```text
Web/H5
  │  上传、确认、纠错
API Gateway / Auth / Rate Limit
  ├─ 文件安全扫描与解析服务
  ├─ PII 识别与脱敏服务
  ├─ 用户档案与同意管理
  ├─ AI 编排层
  │   ├─ 事实抽取模型
  │   ├─ 追问规划器
  │   ├─ 岗位匹配与规则引擎
  │   ├─ 检索服务（岗位/公司知识库）
  │   ├─ 报告生成模型
  │   └─ 输出验证器
  ├─ 行动计划/通知服务
  ├─ 顾问与运营后台
  └─ 审计、监控、风险工单
```

关键设计是把“事实抽取、规则/检索、文字生成、输出校验”拆开。模型不直接从原始文件一步生成最终报告。

## 3. 数据分类

| 级别 | 数据 | 默认控制 |
|---|---|---|
| L4 高敏 | 证件号、金融账户、健康、精确住址、未成年人信息 | 非必要不采集；识别后遮盖/阻断；单独同意与严格访问 |
| L3 敏感业务个人数据 | 原始简历、联系方式、完整对话、顾问笔记 | 加密、短期保存、严格 RBAC、下载水印/审计 |
| L2 一般个人数据 | 结构化经历、偏好、行动与投递反馈 | 按账户隔离、可导出删除 |
| L1 运营数据 | 匿名聚合指标、公开岗位知识 | 去标识化、来源和版本管理 |

简历中还可能包含推荐人姓名、客户名称、内部项目等第三方信息或商业秘密。产品应提示用户删除无关第三方信息，默认不把此类内容沉淀到知识库。

## 4. 数据生命周期

### 4.1 采集

- 上传前说明用途、类型、保存期限、第三方处理者和用户权利；
- 必填字段仅限完成诊断所需内容；
- 敏感个人信息如确有必要，应采用单独同意；
- 不将营销同意与完成诊断捆绑。

### 4.2 处理

- 原始文件先扫描，解析后生成脱敏分析副本；
- 发给第三方模型前删除姓名、电话、邮箱、详细地址、证件号等非分析必要字段；
- 模型请求使用租户隔离的服务端密钥，不在前端暴露；
- 供应商设置为不保留或最短保留、不得用于训练；
- 生产日志不得记录原始简历和完整提示词正文。

### 4.3 保存建议

| 数据 | 默认期限 | 用户选择 |
|---|---|---|
| 未完成上传临时文件 | 24 小时内 | 不延长 |
| 原始简历 | 30 天 | 可提前删除；主动选择长期档案时延长 |
| 脱敏结构化档案 | 账户存续期或用户删除 | 可逐项纠错、导出、删除 |
| 报告版本 | 账户存续期或用户删除 | 可删除单份 |
| 模型调试内容 | 默认不含个人正文，保留必要元数据 | 不用于训练 |
| 安全审计日志 | 按法务和安全策略确定 | 与业务正文分离 |

期限是产品建议，最终应由法务、业务目的和供应商能力共同确认。

### 4.4 删除

删除编排覆盖：对象存储、业务数据库、搜索索引、缓存、向量库、模型供应商可控留存和分析系统。备份中无法即时删除的数据应停止其他处理、设置到期清除并采用严格保护。

## 5. 同意与权限

至少拆分为：

1. 完成诊断所必需的个人信息处理；
2. 保存为长期职业档案；
3. 与指定真人顾问共享；
4. 接收行动提醒；
5. 接收营销信息；
6. 使用去标识化样本改进系统（如需要，单独可撤回；不等于基础模型训练）。

权限角色：用户本人、受邀顾问、质检人员、安全管理员、系统服务账号。运营人员默认只能看脱敏内容；临时查看原文需工单、理由、时限和审计。

## 6. 安全控制

- TLS 传输加密；对象存储和数据库使用托管密钥加密；
- 不同环境、租户和数据类别隔离；
- 短时签名下载链接，禁止公开桶；
- 管理后台强制 MFA、最小权限和会话超时；
- 上传文件类型白名单、内容嗅探、恶意文件扫描和宏禁用；
- 防提示注入：简历和 JD 仅作为不可信数据，不能改变系统指令；
- 检索库写入必须经过审核，网页文本不能直接提升为可信指令；
- 输出防泄露检查：联系方式、证件号、第三方隐私、系统提示词；
- 速率限制、异常下载告警、批量枚举检测；
- 供应链清单、依赖扫描、密钥轮换、备份恢复演练；
- 高危安全事件具备暂停模型调用和冻结导出的开关。

## 7. 模型与供应商治理

选型时必须确认：

- 数据处理地域与跨境路径；
- 请求/响应是否保留、保留多久、是否用于训练；
- 子处理者清单和变更通知；
- 删除、审计、加密和事件通知能力；
- 是否为境内已备案/登记的生成式 AI 服务，以及产品公示义务；
- SLA、速率、成本、上下文长度和中文简历能力；
- 模型版本升级是否可控，是否支持固定版本与回滚。

不得仅凭模型公开宣传决定是否可承载真实简历。

## 8. 公平与自动化决策

- 求职建议属于高影响建议，应向用户解释主要依据和不确定性；
- 不采集或使用性别、民族、宗教、婚育、健康等非必要特征进行分层；
- 照片默认不进入分析；姓名应在分析副本中替换为匿名标识；
- 学历、年龄等容易形成代理歧视的字段，需要逐岗位证明其必要性；
- 对不同学校层次、性别暗示、空档期、海外/国内经历做成对公平测试；
- 用户可请求人工复核并纠正错误事实；
- 商业转化模型不得利用脆弱性或焦虑程度差别定价/施压。

## 9. 生成式 AI 与拟人化互动要求落地

- 对话页和报告显著标识 AI 生成；导出内容保留必要的 AI 标识；
- 用户协议说明生成内容标识方式和使用注意事项；
- 提供投诉举报入口、处理时限和人工联系渠道；
- 长时间连续对话提供 AI 身份与使用时长提醒；
- 不暗示机器人具有人类情感、真实顾问身份或保证能力；
- 对极端情绪、自伤或重大财产损失表达采用专门安全流程，不继续进行普通求职施压；
- 上线前由法务判断产品是否属于相关备案、登记、安全评估或拟人化互动服务范围。

## 10. 事件响应

### P0 事件

大规模简历泄露、跨用户数据串读、公开对象存储、模型供应商异常留存、证件信息外泄。动作：立即阻断、保全日志、通知负责人、评估监管和用户通知义务。

### P1 事件

单用户数据误展示、严重歧视性建议、虚构大量在招信息、删除未完成。动作：冻结结果、修复、通知用户、做根因分析和回归测试。

### P2 事件

局部事实抽取错误、过期条目、普通不当表达。动作：纠正内容、加入评测集、按周复盘。

## 11. 上线合规清单

- 完成个人信息清单、处理目的和数据流图；
- 完成个人信息保护影响评估并留档；
- 完成用户协议、隐私政策、简明告知和单独同意；
- 确认未成年人识别与监护人同意机制；
- 完成第三方模型/云服务的数据处理协议和安全审查；
- 完成生成内容标识、模型备案信息公示和投诉入口；
- 完成用户访问、更正、导出、删除、撤回流程；
- 完成安全测试、权限复核、应急演练和供应商退出预案；
- 对产品是否构成网络招聘/人力资源服务业务做牌照与经营边界核验。

## 12. 法规与官方参考

上线前应以最新法规及正式法律意见为准：

- [《中华人民共和国个人信息保护法》](https://www.npc.gov.cn/WZWSREL25wYy9jMi9jMzA4MzQvMjAyMTA4L3QyMDIxMDgyMF8zMTMwODguaHRtbD9yZWY9aW1i)：目的明确、最小必要、敏感个人信息单独同意、个人权利与影响评估。
- [《网络数据安全管理条例》](https://app.www.gov.cn/govdata/gov/202409/30/520076/article.html)：自 2025-01-01 起施行，覆盖网络数据处理、安全措施和个人信息保护。
- [《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898326795531.htm)：生成式 AI 服务、训练数据、内容安全、投诉及相关备案要求。
- [《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm?s=08)：显式/隐式标识及用户协议提示要求。
- [《人工智能拟人化互动服务管理暂行办法》](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)：自 2026-07-15 起施行，涉及 AI 身份、依赖提示、安全责任和极端情境处置。
- [人社部关于规范招聘信息、促进平等就业的通知](https://rsj.changzhi.gov.cn/zwxx/zcfg/202410/t20241030_2977113.html)：招聘条件应与岗位需要相关，不得实施就业歧视。
- [《人力资源市场暂行条例》](https://xzfg.moj.gov.cn/front/law/detail?LawID=437)：求职、招聘信息真实性、合法性和人力资源服务活动规范。
