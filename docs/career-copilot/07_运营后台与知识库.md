# 运营后台与知识库

> 版本归属：长期开发版（已冻结）  
> 当前不建设运营后台或在线知识库；MVP 使用构建期维护的静态数据包，规范见 [MVP 内容与规则库规范](./MVP前端版/06_MVP内容与规则库规范.md)。

## 1. 目标

公司和岗位推荐的可信度主要取决于外部事实与知识运营，而不只取决于模型。本方案明确以网络公开、可核验数据为核心：外部来源负责“是否存在、是否在招、岗位要求是什么”，内部顾问负责“如何映射到岗位画像、对某类学生意味着什么、层级是否合理”。所有影响分层的市场信息都必须有来源、时效、审核人和失效机制。

## 2. 知识对象

### 2.1 岗位族

字段：名称、别名、核心任务、必要门槛、加分项、能力维度、替代证据、常见误区、实习/校招差异、适用行业、来源、顾问审核人、版本、有效期。

### 2.2 公司岗位条目

字段：公司、业务线（可确认时）、岗位族、具体岗位、地点、招聘类型、批次、官方链接、开放/关闭/未知状态、门槛、偏好、来源、核验时间、失效时间、审核状态。

### 2.3 信息来源等级

1. A 级：公司招聘官网、官方公众号、正式招聘公告；
2. B 级：公司认证招聘账号、可信招聘平台的官方发布；
3. C 级：顾问基于真实案例的结构化经验，需注明时间和适用范围；
4. D 级：用户反馈、社区讨论，仅作线索，不直接作为事实。

“在招”状态原则上只由 A/B 级来源支持。C/D 级信息必须用“经验观察/待核验”表达。

### 2.4 外部数据覆盖规则

- 100% 的公司岗位卡必须附至少一个可访问的外部来源；
- 100% 的“正在招聘”状态必须由企业官方页面、正式公告、政府公共就业平台或经授权数据接口支持；
- 内部顾问经验可以调整匹配解释和层级，但不能单独创建实时岗位事实；
- 网络数据冲突时，企业官方招聘页面优先，其次为政府平台，再其次为经授权聚合平台；
- 用户提供的 JD 默认不进入公共库，只在当前用户空间使用；
- 不为追求覆盖率采集来源不明的简历、面经或个人联系方式。

## 3. 条目工作流

```text
采集 → 自动去重/格式化 → 编辑核验 → 顾问审核 → 发布 → 到期提醒 → 复核或下线
```

- 同一人不得在高影响条目上同时完成采集与最终审核；
- 每次修改记录差异、理由和责任人；
- 到期未复核的条目自动从实时推荐中撤下；
- 来源失效或内容冲突自动进入待处理队列。
- 每种外部来源上线采集器前必须记录授权依据、网站条款/robots 检查、允许字段、频率限制和退出方式。

## 4. 后台模块

### 4.1 知识库管理

搜索、筛选、批量到期、版本对比、来源预览、重复合并、审核发布、回滚、失效影响分析。

### 4.2 报告质检

按模型版本、方向、置信度、用户异议、安全命中抽样。质检标签：

- 事实抽取错误；
- 证据不足；
- 岗位逻辑错误；
- 公司层级不合理；
- 信息陈旧/来源错误；
- 行动不可执行；
- 语气不当；
- 歧视或敏感信息风险；
- 商业转化过度。

### 4.3 顾问复核

顾问只看到用户授权范围。界面先展示争议结论、低置信项和关键缺口，再展示完整报告。顾问可：确认、调整层级、补充原因、发起追问、建议服务。所有修改留版本。

### 4.4 风险工单

隐私、歧视、危机、知识错误、删除失败、跨用户访问分别设责任队列、严重度、处理 SLA 和升级路径。

## 5. 运营 SLA 建议

- 新增首发岗位画像：两名对应赛道顾问审核后发布；
- 官方招聘状态：高峰期至少每 7–14 天复核；
- 用户举报的虚假在招：2 小时内下线待查，1 个工作日内处理；
- 严重歧视或隐私投诉：立即冻结结果并升级；
- 普通报告质检：每周抽检，覆盖新模型、新赛道和低置信样本；
- 新模型上线后一周提高抽检比例。

## 6. 顾问反馈闭环

顾问调整必须选择原因，系统每周汇总：

- 哪些岗位画像导致最多误判；
- 哪类证据经常被高估或低估；
- 哪些公司层级需要按业务线细分；
- 哪些追问对改变结论最有效；
- 哪些建议用户最常标记“不适用”。

反馈先进入评测集和规则优化，不得未经授权直接拿真实简历训练基础模型。

## 7. 服务推荐规则

仅当报告出现可由具体服务解决的差距时展示服务卡：

| 触发条件 | 可推荐服务 | 必须说明 |
|---|---|---|
| 表达问题为主要阻碍 | 简历优化 | 哪几处证据需要重构、交付物是什么 |
| 方向冲突且高影响 | 1v1 咨询 | 需要人工判断的关键问题 |
| 面试反馈反复指向同类问题 | 面试辅导 | 需要训练的场景和目标 |
| 整个招聘周期任务复杂 | 实习/校招陪跑 | 周期、边界和陪跑价值 |

禁止：人为降低评价、使用倒计时恐吓、暗示“不付费就没有机会”、隐藏免费的自助行动方案。

## 8. 内容治理

- 所有示例简历、案例和报告必须脱敏或获得明确授权；
- 不公开可重新识别个人的学校、年份、公司、项目组合；
- 用户反馈不能直接作为宣传素材；
- 公司评价避免无来源的贬损或传闻；
- 薪资只展示有可靠来源的区间、地区、职级和时间；
- 运营文案每季度做一次公平、合规和时效审查。

## 9. 运营看板

建议显示：知识覆盖率、有效条目率、到期率、来源等级分布、举报率、顾问推翻率、主要误判类型、各赛道报告量和等待复核时长。不得显示可识别用户的公开排行榜。

## 10. RACI

| 工作 | 产品 | AI/研发 | 赛道顾问 | 运营 | 安全/法务 |
|---|---|---|---|---|---|
| 评估框架 | A | C | R | C | C |
| 岗位画像 | C | C | A/R | R | I |
| 公司条目 | I | C | A | R | C |
| 模型评测 | A | R | R | C | C |
| 隐私与安全 | C | R | I | I | A |
| 报告质检 | A | C | R | R | C |
| 投诉处置 | C | C | C | R | A |

A=最终负责，R=执行，C=协作，I=知会。
