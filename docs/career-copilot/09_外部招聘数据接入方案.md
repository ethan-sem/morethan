# 外部招聘数据接入与网络知识库方案

> 版本归属：长期开发版（已冻结）  
> 当前 MVP 不运行爬虫、同步任务或数据服务；只使用人工核验后随前端构建发布的静态数据，见 [MVP 内容与规则库规范](./MVP前端版/06_MVP内容与规则库规范.md)。

> 版本：v1.0-draft  
> 日期：2026-08-09  
> 产品决策：网络数据为核心，内部顾问负责维护、解释和校准

## 1. 结论先行

外部数据可以成为智能求职助手的核心，但首版不能依赖“一个免费 API 覆盖国内所有招聘岗位”的假设。

当前可行性分为三类：

1. **可直接作为公开事实来源**：企业官方招聘网站/公告、国家大学生就业服务平台、中国公共招聘网、全国就业公共服务平台等公开页面。适合核验岗位、批次、地点与要求；是否允许自动批量采集需逐站确认。
2. **存在官方 API，但需要租户授权或商业合作**：Moka、北森、牛客等 ATS/招聘服务 API。它们证明技术接入可行，但通常只开放给相应企业客户或合作方，并不是免费全市场职位库。
3. **公开 API/数据集可直接用于标准化和研发**：ESCO 职业技能 API、国家职业分类与职业标准、Chinese-SkillSpan 等研究数据。它们适合岗位分类、技能抽取和评测，不等于实时招聘岗位。

因此建议采用：

> **官方网络事实层 + 职业技能标准层 + MoreThan 顾问解释层 + 用户 JD 长尾补充层**

其中网络数据决定事实，顾问经验决定解释；任何一方都不能单独制造“录取概率”。

## 2. 数据目标

外部数据只服务以下明确任务：

- 确认某公司是否存在公开实习/校招机会；
- 获取岗位名称、地点、批次、职责、要求、申请链接和更新时间；
- 把不同公司的职位映射到统一岗位族与技能体系；
- 识别岗位要求的共性、差异和变化趋势；
- 为用户生成可核验的公司岗位池和定向差距；
- 为模型评测提供公开、可复现的任务样本。

不采集：求职者简历、个人联系方式、聊天记录、未公开候选人数据、付费面经全文、绕过登录/验证码才能访问的数据。

## 3. 建议数据源清单

### 3.1 第一优先级：企业官方招聘页与公告

适用数据：职位、地点、实习/校招类型、批次、JD、申请链接、发布时间/更新时间。

优点：最接近事实源；可直接回链供用户核验。  
局限：站点结构分散，部分由 Moka、北森、自研系统或小程序承载；页面结构和反自动化策略会变化。

接入方式：

- 优先使用页面自带结构化数据、公开 JSON 或招聘系统明确开放的只读接口；
- 没有接口时，先做“官方链接登记 + 定期人工/半自动核验”；
- 只有在网站条款、robots 规则和技术许可允许时才建立低频采集器；
- 用户投递始终跳转企业官方页面，首版不代投。

### 3.2 第一优先级：国家与公共就业平台

建议纳入：

- [国家大学生就业服务平台职位信息](https://www.ncss.cn/student/jobs/index.html)：面向高校毕业生，适合实习/校招发现与官方活动补充；
- [中国公共招聘网高校毕业生招聘](https://www.job.mohrss.gov.cn/cjobs/colleges/listColleges)：包含高校毕业生、事业单位、重点行业与企业招聘入口；
- [全国就业公共服务平台](https://www.12333.gov.cn/job/?channel=12333)：国家公共就业服务入口；
- 地方人社部门、高校就业网和国资系统的正式招聘公告。

教育部已明确国家 24365 大学生就业服务平台是国家级高校毕业生就业服务平台；公开页面可用于发现和核验，但本轮未发现面向普通第三方开发者的统一开放职位 API。因此首版应先取得书面合作或许可，再决定是否自动同步；在此之前以链接索引和人工核验为主。

### 3.3 第二优先级：ATS 与招聘服务官方接口

| 来源 | 已确认能力 | 现实限制 | 建议 |
|---|---|---|---|
| [Moka 招聘官网 API](https://www.mokahr.com/docs/api/index.html) | 获取招聘官网职位、职位状态、校招/社招模式及投递 | 需要开放平台授权、access token 或企业租户关系 | 联系 Moka 商务，争取只读职位聚合合作；未授权前不使用私有接口 |
| [北森招聘 API](https://s.apifox.cn/apidoc/docs-site/436023/api-6342740) | 招聘与应聘流程接口 | 面向北森客户集成，需开通和企业授权 | 作为未来合作渠道，不视为全市场公共 feed |
| [牛客 API](https://docs.nowcoder.com/) | 企业版 ATS/笔试等系统对接 | 需企业版 apiKey/token，主要服务企业招聘流程 | 洽谈校招岗位数据合作；不得复用企业凭据批量获取无权数据 |
| [Greenhouse Job Board API](https://developers.greenhouse.io/job-board) | 公开 GET 已发布职位，无需认证 | 主要覆盖使用 Greenhouse 的企业，国内校招覆盖有限 | 可作为跨国企业和海外岗位补充适配器 |
| [Lever Postings API](https://github.com/lever/postings-api) | 获取企业公开职位和详情 | 按企业 site 分区，不提供全网搜索 | 可按已确认目标企业建立白名单适配器 |

这些接口表明“按 ATS 建适配器”在技术上可行，但不能把企业自有 API 错当作平台级开放数据。任何商业接口都应先签订数据使用与再展示条款。

### 3.4 基础标准：职业与技能体系

#### 国内职业标准

- [《中华人民共和国职业分类大典（2022 年版）》](https://rsj.shannan.gov.cn/zwgk/zcfg/rsrc/202304/t20230421_118929.html)：作为中文职业名称、编码和职业边界的基础；
- [国家职业标准查询系统](https://osta.mohrss.gov.cn/skillStandard)：提供国家职业标准及职业编码查询；
- 人社部后续发布的新职业、新工种信息用于年度增量更新。

适用：规范岗位族、同义词和职业边界。局限：互联网校招中的“产品经理、增长运营、商业分析”等岗位粒度和公司语境仍需 MoreThan 自建映射。

#### 国际职业技能标准

- [ESCO Web Service API](https://esco.ec.europa.eu/en/use-esco/use-esco-services-api/esco-web-service-api)：提供机器可读的职业、技能、知识和能力关系；
- ESCO 可用于建立技能同义词、多语言映射和岗位—技能图谱。

适用：技能标准化与中英文简历。局限：不能直接代表中国实习/校招的筛选习惯，需要本地顾问和真实 JD 校准。

### 3.5 研发与评测数据

- [Chinese-SkillSpan](https://arxiv.org/abs/2604.23009)：2026 年发布的中文招聘文本技能抽取数据，包含 20,000 余个标注实例，并与 ESCO 的知识、技能、通用能力和语言能力维度对齐；适合做中文 JD 技能抽取基线与评测。
- [SkillSpan](https://github.com/kris927b/SkillSpan)：英文招聘文本技能/知识跨度数据，可用于英文简历与 JD 处理评测。
- [ConFit v2](https://aclanthology.org/2025.findings-acl.661.pdf)：简历—岗位匹配研究，可用于理解对比学习、难负样本和匹配评测设计。
- 阿里云天池历史职位—简历匹配竞赛数据在研究中被多次使用，但正式使用前必须重新确认数据是否仍可下载、具体许可、是否包含个人信息及是否允许商业用途；未完成审查前不得进入生产。

研究数据只能用于算法研发和评测，不能用其历史职位冒充当前在招，也不能把论文指标直接解释为用户录取概率。

## 4. 首版数据架构

```text
外部来源注册表
  ├─ 企业官网/公告适配器
  ├─ 公共就业平台链接索引
  ├─ 获授权 ATS API
  └─ 用户提交 JD（私有）
          ↓
原始快照层（来源、时间、哈希、许可标签）
          ↓
解析与标准化层（公司、岗位、地点、批次、技能）
          ↓
去重与实体解析（同公司/同岗位/同批次）
          ↓
外部事实库 ── 职业技能标准库
          ↓              ↓
       顾问解释与岗位映射库
                  ↓
        用户匹配、分层与可追溯报告
```

### 4.1 来源注册表字段

- `source_id`、名称、域名、来源等级；
- 数据所有者与联系方式；
- 公开页面/API/人工录入类型；
- 使用依据：公开展示、书面授权、合同或开放许可；
- 条款和 robots 检查日期；
- 允许字段、抓取频率、缓存期限和再展示限制；
- 适配器负责人、故障联系人和停止采集开关；
- 最近成功同步、错误率和下次复核时间。

### 4.2 岗位事实字段

- 公司、业务线、职位原名、标准岗位族；
- 实习/校招、面向届别、地点、部门；
- 职责、要求、申请链接；
- 官方开放/关闭/未知状态；
- 首次发现、最近看见、最近核验；
- 来源 URL、原文哈希、快照引用；
- 许可标签和可展示字段；
- 技能实体与证据片段；
- 顾问解释、适用范围与审核版本。

## 5. 数据新鲜度与状态机

```text
新发现 → 待标准化 → 待核验 → 可推荐
   └──────── 冲突/许可不明 → 冻结
可推荐 → 到期复核 → 继续有效 / 已关闭 / 无法确认
```

- 企业官方职位建议每日或每 1–3 天低频检查，具体频率服从来源许可；
- 公共平台岗位建议 7 天复核；
- 招聘批次公告在关键季节每日检查，非招聘季降低频率；
- 页面消失不立即认定职位关闭，先进入“无法确认”；
- 连续两次核验失败、来源冲突或超过 SLA 时，从“在招推荐”降级为“历史/目标公司参考”；
- 用户报告保留当时来源与核验时间，避免历史报告随数据库静默改变。

## 6. 外部数据驱动的推荐规则

1. 公司岗位卡必须至少有一个外部来源；
2. “正在招聘”必须有有效官方或授权来源；
3. 公司品牌、规模或顾问印象不能单独决定层级；
4. 层级计算以用户证据与具体 JD 为主，外部市场事实负责门槛和机会窗口；
5. 内部顾问可以覆盖系统层级，但必须记录理由和适用范围；
6. 多来源冲突时展示冲突并要求用户前往官方页面确认；
7. 无实时岗位时可以推荐“目标公司 × 岗位族”，但必须明确不是在招信息。

## 7. 实施优先级

### 第 0 阶段：两周验证

- 建立 30 家目标企业白名单，覆盖互联网、技术、商科、金融与国央企；
- 记录其招聘官网技术栈、页面结构、robots/条款、是否存在公开 JSON；
- 对接国家大学生就业服务平台、中国公共招聘网和全国就业公共服务平台，询问数据合作方式；
- 联系 Moka、北森、牛客获取职位只读数据合作与报价；
- 下载并审查 ESCO、国家职业分类及 Chinese-SkillSpan 的许可和字段。

交付：来源可行性矩阵、许可清单、样例标准化数据和成本估算。

### 第 1 阶段：MVP 数据底座

- 100 家重点企业官方来源；
- 6–8 个首发岗位族；
- 企业官网链接登记、变更检测和人工核验后台；
- 至少接入一种明确允许的公开/授权 ATS 适配器；
- 用户粘贴 JD 的私有分析；
- 公司岗位卡 100% 外部来源覆盖。

不以岗位总量作为上线目标，优先保证来源真实、适合实习/校招且可以持续更新。

### 第 2 阶段：扩大网络覆盖

- 与公共就业平台、ATS 或招聘服务商建立正式数据合作；
- 扩展重点公司、地方国企、高校就业网和行业专场；
- 引入来源质量评分、自动去重和岗位变化检测；
- 基于用户点击官方申请页和主动提交的投递结果校准推荐，但不采集外部平台账户数据。

## 8. 建议的采购/合作问题

向任何数据供应商询问：

1. 是否允许用于求职者端岗位推荐和 AI 分析？
2. 是否允许缓存、标准化、展示 JD 摘要和申请链接？
3. 覆盖哪些企业、实习/校招比例、更新频率和关闭通知？
4. 是否提供稳定 ID、增量同步、删除事件和历史版本？
5. 数据是否包含个人信息或未经授权内容？
6. 是否允许模型处理，是否允许用于评测或训练？
7. SLA、调用限制、计费、退出和数据删除条款是什么？
8. 发生错误、侵权或安全事件时双方责任如何划分？

## 9. 禁止做法

- 绕过登录、验证码、反爬或访问控制；
- 使用个人账号 cookie 批量采集招聘平台；
- 在无授权时复制整个商业招聘平台职位库；
- 将公开可见等同于允许批量抓取、长期缓存和商业再利用；
- 从论坛、群聊、面经帖推断公司实时招聘状态；
- 保存或传播招聘联系人、求职者简历等个人信息；
- 让模型凭常识补全来源、岗位编号、招聘批次或薪资；
- 因外部数据不足而虚构公司清单凑数。

## 10. 成功标准

- 公司岗位卡外部来源覆盖率 100%；
- “在招”卡片官方/授权来源覆盖率 100%；
- 有效链接率 ≥ 98%；
- 到期复核 SLA 达成率 ≥ 95%；
- 来源冲突自动冻结率 100%；
- 用户可一键打开原始来源核验；
- 顾问只对解释和分层负责，不承担手工复制全网职位的主要工作；
- 不发生未经授权采集、访问控制绕过或个人信息进入公共库。

## 11. 最终建议

首版不要等待大型平台开放全量 API，也不要先造一个高风险爬虫系统。应立即推进三条相互独立的路线：

1. 用 100 家重点企业官方招聘源建立高质量实时岗位池；
2. 用国家职业分类、ESCO 与中文技能数据构建岗位—技能标准层；
3. 与公共就业平台和主流 ATS 厂商洽谈正式只读数据合作。

这样既满足“网络数据为核心”，又能让内部顾问把时间投入在真正有价值的岗位解释、分层校准和报告质检上。
