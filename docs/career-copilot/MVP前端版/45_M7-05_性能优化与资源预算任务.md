# M7-05 性能优化与资源预算任务

> 文档状态：已完成  
> 任务状态：`[done]`（2026-08-19）  
> 适用版本：MoreThan 智能求职助手 MVP 前端版  
> 前置任务：M7-04 完成或不存在影响测量的 P0/P1 布局与交互问题  
> 核心原则：按需加载、解析不阻塞、结果不降级、隐私边界不改变  
> 实施记录：`49_M7-05_性能优化与资源预算实施记录.md`

## 1. 任务目标

在不增加后端、不上传简历、不删减免费功能的前提下，降低 MoreThan 官网和智能求职助手的初始下载、解析等待与交互阻塞，并建立可持续的性能预算门禁。

本任务需要解决四个核心问题：

1. 未进入求职助手的官网用户不应下载求职助手完整业务代码；
2. 未选择 PDF/DOCX 的用户不应提前下载相应解析器和 Worker；
3. 公司岗位知识数据、报告组件和后续分析模块应在真正需要时加载；
4. 后续代码或数据增长超过预算时，生产构建必须给出明确失败，而不是依赖人工发现。

## 3. 性能预算

### 3.1 资源预算

| 预算项 | 目标 | 阻断条件 |
|---|---:|---|
| 官网初始 JS | gzip 不超过 180KB | 超过 200KB 阻断构建 |
| 官网初始 CSS | gzip 不超过 35KB | 超过 45KB 阻断构建 |
| 求职助手首次进入附加 JS | gzip 不超过 140KB | 超过 170KB 阻断构建 |
| 求职助手首次进入附加 CSS | gzip 不超过 25KB | 超过 35KB 阻断构建 |
| 公司岗位池静态数据 | gzip 不超过 60KB | 超过 80KB 阻断构建 |
| 单个非解析器业务 chunk | gzip 不超过 100KB | 超过 120KB 阻断构建 |
| 首屏必要图片单张 | 不超过 250KB | 超过 350KB 且非明确例外时阻断 |

PDF.js、Mammoth 和解析 Worker 属于按格式触发的重型依赖，不计入官网或求职助手开始页的初始预算，但必须确保不会预加载。

### 3.2 用户体验目标

在发布验收的中端移动设备/等效节流环境中，以实验室数据作为上线前参考：

- LCP：不超过 2.5 秒；
- CLS：不超过 0.1；
- INP 或等效交互延迟：不超过 200ms；
- 从点击官网入口到助手开始页可操作：缓存冷启动不超过 1.5 秒；
- 点击“开始免费诊断”到材料页可操作：不超过 500ms；
- 选择文件后 200ms 内出现解析状态；
- 解析期间主线程不出现连续 200ms 以上阻塞；
- 用户点击取消后 300ms 内停止进度更新并恢复可操作状态。

真实公网指标可能受网络、设备和托管节点影响。本任务建立的是发布前实验室目标，不伪造线上 P75 数据。

## 4. 优化范围

### 4.1 官网与求职助手路由分包

- 将求职助手页面由官网主入口的同步导入改为路由级动态导入；
- 用户未点击智能求职助手入口时，不请求助手页面、领域分析和助手专用样式；
- 加载期间显示与品牌一致的轻量状态，不出现空白页、布局跳变或不可操作的假按钮；
- 动态模块加载失败时提供重试和返回官网路径；
- 不使用会提前下载全部助手资源的无条件预加载；
- 可在用户明确悬停、聚焦或即将进入入口时做低风险预取，但必须验证不会影响首页关键资源。

### 4.2 助手内部按阶段加载

建议按用户流程拆为以下边界，具体 chunk 方案以构建分析结果为准：

1. 开始页与材料输入；
2. 事实确认与求职目标；
3. JD、分析规则与生成流程；
4. 报告、公司推荐与证据展开；
5. 行动计划与数据设置。

要求：

- 开始页不得为尚未访问的报告和设置页面付出完整下载成本；
- 动态加载不得重置当前内存状态；
- 组件切换时应保留可访问的加载状态和错误恢复；
- 不为了追求 chunk 数量而产生大量几十字节的小请求；
- React、图标库和通用组件避免在多个 chunk 中重复打包。

### 4.3 解析器与 Worker

- TXT、PDF、DOCX 按用户实际选择的格式分别加载；
- PDF 用户不得下载 DOCX 解析器，DOCX 用户不得下载 PDF.js；
- 直接粘贴和手工填写不得下载 PDF.js 或 Mammoth；
- 文件校验应在重型依赖加载前完成，超限、伪装或空文件直接失败；
- 二进制继续使用 transferable 传递，避免主线程和 Worker 双份复制；
- 事实提取继续在 Worker 中执行，不能因优化回退到主线程；
- Worker 完成、取消、超时、重置和页面卸载后均正确终止并释放引用；
- 不设置无限保留的 Worker 池或隐式持久缓存。

### 4.4 静态公司与岗位数据

- 移除公司岗位池在助手入口模块中的同步 JSON 导入；
- 只在报告即将需要公司推荐时请求 `public/data/career-copilot/` 中对应数据；
- 优先按首发方向拆分数据，避免用户只看一个方向却下载全部方向记录；
- Schema 版本、数据版本、核验日期和校验规则不得因分包丢失；
- 加载失败时保留完整个人分析报告，只把公司推荐降级为“暂时无法读取目标池”；
- 不将公开静态数据加载失败误报为简历或个人分析失败；
- 静态数据请求不得携带简历、JD、事实 ID 或其他用户材料；
- 知识数据允许使用静态缓存，但更新发布后必须有可控的版本失效机制。

### 4.5 图片、字体与样式

- 智能求职助手页面不得下载只属于官网其他页面的大图和团队照片；
- 首屏以现有 CSS、字体和图标体系为主，不新增装饰性重图；
- 非首屏图片使用尺寸属性和延迟加载，减少 CLS；
- 评估现有 PNG/JPEG 的 WebP/AVIF 转换，不接受肉眼可见的品牌质量回退；
- 字体使用合理的回退栈，避免字体等待阻塞主要中文内容；
- 助手样式按路由加载后必须保持打印样式完整，不能破坏 M7-04 验收结果；
- 删除实际未使用的样式和图标导入，但不得以全局正则误删动态引用。

## 5. 加载策略

### 5.1 允许的加载时机

| 资源 | 最早允许加载时机 |
|---|---|
| 助手开始页代码 | 用户进入或明确意图进入助手 |
| 材料与事实页面 | 进入助手后可顺序预取 |
| PDF 解析器 | 通过 PDF 基础校验后 |
| DOCX 解析器 | 通过 DOCX 基础校验后 |
| 事实提取 Worker | 文本提取即将完成时 |
| 分析规则与报告代码 | 用户完成事实确认后 |
| 对应方向公司数据 | 报告生成前或报告展示时 |
| 打印相关逻辑 | 报告可用后 |

### 5.2 禁止行为

- 首页加载时无条件预取全部助手代码；
- 用户粘贴文字时下载 PDF.js/Mammoth；
- 把简历或 JD 放入 Service Worker、Cache Storage 或持久化缓存；
- 为复用缓存而把用户文本拼入静态数据 URL；
- 用假进度条掩盖主线程长时间冻结；
- 为体积数字删除错误反馈、免责声明、来源追溯或隐私控制；
- 以降低分析精度、事实覆盖或公司数据完整性换取预算通过。

## 6. 测试样本与性能场景

### 6.1 页面加载场景

- 直接访问官网首页，确认无求职助手业务 chunk 请求；
- 冷缓存进入求职助手；
- 热缓存再次进入求职助手；
- 慢速网络下进入助手，检查加载状态与重试；
- 助手 chunk 加载失败，检查错误恢复；
- 320px、375px 和 1440px 下检查布局稳定性。

### 6.2 解析场景

- 直接粘贴纯虚构简历；
- TXT 小文件；
- 5 页、20 页文本型 PDF；
- 常规和较大 DOCX；
- 接近 10MB 上限的合法测试文件；
- 超限、损坏、加密和空文件；
- 解析中取消、切换文件、清除数据和离开页面。

所有性能材料必须使用 M7-01 匿名样本或程序生成内容，不得使用真实求职者简历。

## 7. 测量与证据

每轮验证至少记录：

- 构建日期、提交或文件版本；
- 浏览器、系统、视口和设备/模拟配置；
- 冷缓存与热缓存；
- 各入口 chunk 的 raw、gzip 和 Brotli 大小；
- 页面实际请求清单、请求时机与传输大小；
- LCP、CLS、交互延迟和长任务；
- PDF/DOCX/TXT 的解析耗时、首次状态时间、取消响应时间；
- Worker 创建与销毁记录；
- 优化前后对比及功能回归结果。

不允许只引用构建工具的总包大小就宣称页面性能通过。

## 8. 自动化性能门禁

新增构建期性能检查，至少完成：

- 读取构建 manifest 并识别官网入口、助手入口、业务 chunk、解析 Worker 和静态数据；
- 计算 raw、gzip，条件允许时同时计算 Brotli；
- 检查官网入口不得静态依赖助手完整模块；
- 检查粘贴流程入口不得静态依赖 PDF.js 或 Mammoth；
- 检查公司岗位池不得重新进入主入口 bundle；
- 检查预算超限时以非零状态阻断生产构建；
- 输出人类可读的资源清单和与预算的差值；
- 对批准的解析器大文件使用精确白名单，禁止模糊放行整个目录。

预算首次执行时可以基于新的分包结构调整一次，但任何放宽都必须在 M7-05 实施记录中说明原因和影响。

## 9. 缺陷等级

| 等级 | 定义 | 示例 | 发布处理 |
|---|---|---|---|
| P0 | 阻断使用、破坏数据安全或造成页面冻结 | 解析大文件导致页面长期无响应；静态缓存保存简历 | 禁止发布 |
| P1 | 核心性能预算或按需加载边界失效 | 首页下载 PDF.js；助手仍全部进入主包 | M7-05 结束前修复 |
| P2 | 有明显性能损失但不阻断流程 | 报告模块预取过早；图片体积偏大 | M7-07 前尽量关闭 |
| P3 | 轻微或仅特定设备可见 | 非关键资源还有小幅压缩空间 | 进入后续优化池 |

## 13. 完成定义

M7-05 标记 `[done]` 必须同时满足：

- 官网首页不下载求职助手完整业务代码；
- 粘贴、手填、TXT、PDF、DOCX 均只加载各自需要的解析资源；
- 公司岗位数据只在报告阶段按需读取，失败不会破坏个人报告；
- Worker 解析期间页面可交互，取消和清除可及时终止任务；
- 资源预算门禁已进入生产构建并能对故意超限返回失败；
- 实验室 LCP、CLS、交互延迟和解析响应达到本任务目标，或对无法达到项给出经管理层接受的书面例外；
- M7-02 自动化、M7-04 无障碍/响应式/打印回归、类型检查、代码检查和生产构建全部通过；
- 网络请求和缓存中不存在简历、JD、事实、报告或密钥；
- 有可复核的优化前后数据，不能只凭主观感受宣称完成。

仅增加 `React.lazy`、减少一个文件或看到构建成功，不足以关闭 M7-05。

## 14. 执行结果

2026-08-19 已完成本任务全部代码、数据和自动化门禁：官网—助手路由、助手流程阶段、分析管线、解析 Worker 与公司方向数据均已建立按需加载边界；首屏主图改为 27.35KB WebP；资源预算、边界检查和故意超限反向测试均接入 `pnpm run check`。

最终预算结果：官网初始 JS 74.52KB gzip、官网初始 CSS 7.80KB gzip、助手首次进入附加 JS 19.34KB gzip、助手附加 CSS 12.82KB gzip、最大单方向公司数据 2.03KB gzip，全部达到目标值。内置 Chromium 实验室采样得到 FCP 152ms、CLS 0、交互事件 16ms、200ms 以上长任务 0；该环境未产出 LCP 条目，因此没有用 0 冒充有效 LCP，公网 P75 继续在正式托管后采集。

最终全量门禁通过：56 个测试文件、318 项测试，以及 lint、TypeScript、PDF.js/Mammoth 依赖探针、静态数据、匿名样本、隐私、无障碍、浏览器兼容、生产构建、性能预算和反向失败测试。详见实施记录和 `outputs/career-copilot/m7-05-performance-budget.json`。
