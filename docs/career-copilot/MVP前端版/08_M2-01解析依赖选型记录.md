# M2-01 浏览器解析依赖选型记录

> 决策日期：2026-08-09  
> 状态：已完成选型、安装、构建探针与生产依赖安全审计  
> 范围：只确认依赖与加载边界，不实现 PDF/DOCX 正式解析器

## 1. 选型结论

| 文件 | 选用依赖 | 锁定版本 | 许可证 | 选用方式 |
|---|---|---:|---|---|
| PDF | `pdfjs-dist` | 6.2.108 | Apache-2.0 | 动态加载 Display API 与独立 Worker，只读取本地 `Uint8Array` |
| DOCX | `mammoth` | 1.12.0 | BSD-2-Clause | 动态加载浏览器适配版本，只调用 `extractRawText({ arrayBuffer })` |

版本使用精确锁定而非范围：PDF.js 的 API 与 Worker 必须版本一致；Mammoth 官方也建议依赖其行为时固定版本并在升级前回归测试。

## 2. 官方能力核验

### PDF.js

- Mozilla 官方项目，目标是用 Web 标准解析和渲染 PDF；npm 发行包为 `pdfjs-dist`。
- 官方浏览器示例以 `getDocument()` 返回异步加载任务，再逐页读取。
- API 支持二进制数据输入，适合浏览器从用户本地 `File` 得到 `ArrayBuffer/Uint8Array`，无需上传。
- 默认发行包面向当前浏览器；旧浏览器另有 `legacy` 构建。本 MVP 只支持主流浏览器最近两个版本，选择标准构建。
- Worker 独立加载，正式解析器必须在结束或失败后销毁任务和文档对象。

官方来源：

- https://github.com/mozilla/pdf.js
- https://mozilla.github.io/pdf.js/examples/
- https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html
- https://www.npmjs.com/package/pdfjs-dist

### Mammoth

- 官方文档明确支持浏览器 `{ arrayBuffer }` 输入。
- `extractRawText()` 忽略格式并在段落间保留换行，适合后续简历结构识别。
- 从 1.11.0 起默认禁用外部文件访问；本项目仍不得主动启用该能力。
- 官方警告其 HTML 转换结果不负责消毒。因此 MVP 只使用原始文本接口，不把转换 HTML 插入 DOM，也不读取图片或外部链接。

官方来源：

- https://github.com/mwilliamson/mammoth.js
- https://www.npmjs.com/package/mammoth
- https://github.com/mwilliamson/mammoth.js/blob/master/NEWS

## 3. 包体积记录

以下为 2026-08-09 从 npm 官方元数据和已安装发行文件读取的原始体积，不等于最终用户下载量：

| 项目 | npm 解压体积 | 关键发行文件 |
|---|---:|---:|
| `pdfjs-dist@6.2.108` | 34,497,725 B（约 32.9 MiB） | `pdf.min.mjs` 454,669 B；`pdf.worker.min.mjs` 1,262,398 B |
| `mammoth@1.12.0` | 2,166,337 B（约 2.07 MiB） | `mammoth.browser.min.js` 635,882 B |

PDF.js npm 包包含类型、Source Map、字体、字符映射、WASM 和多套构建，不能用整个解压体积推断网页下载量。最终以 Vite 探针产生的实际动态分包及 gzip 结果为准。

实际 Vite 动态分包结果：

| 动态资源 | 构建体积 | gzip |
|---|---:|---:|
| 加载边界 | 0.97 kB | 0.54 kB |
| PDF Display API | 538.17 kB | 141.66 kB |
| PDF Worker | 1,683.37 kB | 566.88 kB |
| Mammoth 浏览器包及依赖 | 657.28 kB | 138.54 kB |

这些资源仅在后续解析器调用动态加载函数时下载。官网正常生产构建的主 JS 仍为 80.85 kB gzip，未因安装解析依赖而增加。

## 4. 候选取舍

### DOCX 未选择 `docx-preview`

`docx-preview` 的主要目标是把 Word 页面视觉渲染成 HTML，稳定接口是 `renderAsync`；内部解析 API被官方标为实验性。MVP 只需要可信文本抽取，不需要字体、分页、图片或 HTML 渲染，因此 Mammoth 的 `extractRawText` 更小、更直接，也减少 HTML 注入面。

官方参考：https://github.com/VolodymyrBaydalka/docxjs

### 不使用在线转换服务

任何 SaaS 文档转换都会把简历传出浏览器，与当前纯前端、本地优先和零账号方案冲突，因此不进入候选。

## 5. 集成边界

- 两个依赖只能通过 `parsers/dependencyProbe.js` 所建立的动态加载边界进入后续解析器。
- 不得静态导入到官网入口，避免增加首屏包体积。
- PDF Worker 使用与 API 相同包版本的文件，不允许 CDN 混用。
- M2-02 调用 `getDocument` 时必须显式设置 `enableScripting: false`，并由网站 CSP 继续限制脚本来源。
- 正式解析只接收本地二进制，不接收远程 URL。
- DOCX 只抽取文本，不转换/渲染 HTML，不处理图片，不允许外部文件访问。
- 解析错误只能记录错误码，不记录文件名和正文。

## 6. 安全审计与版本修正

首次探针曾采用 `pdfjs-dist@6.1.200`。生产依赖审计发现 GitHub Reviewed 高危公告 `GHSA-hq66-cqwq-w95j / CVE-2026-16633`：`>=5.6.83 <6.2.108` 在默认启用脚本且缺少相应 CSP 时，恶意 PDF 可能执行攻击者 JavaScript。项目已在完成 M2-01 前升级至修复版本 `6.2.108`。

修正后执行 `pnpm audit --prod --audit-level high`，结果为无已知生产依赖漏洞。公告：https://github.com/advisories/GHSA-hq66-cqwq-w95j

## 7. 升级观察

PDF.js 已使用包含安全修复的最新版本 `6.2.108`。Mammoth 最新标签 `1.12.1` 于 2026-08-09 当日发布；为降低零日升级的不确定性，本次锁定已核验且稳定时间更长的 `1.12.0`，进入 M2-03 时用匿名 DOCX 夹具验证后再决定是否升级。
