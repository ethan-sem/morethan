# M3-05 低置信与无法确认实施说明

> 完成日期：2026-08-13  
> 状态：已完成  
> 范围：浏览器纯前端、内存态、无账号、无后端、无数据库

## 1. 完成结果

事实确认页现已覆盖用户无法核实、规则置信度不足、关键证据缺失和时间线提示四类情况。用户不必在“确认错误内容”和“永久删除内容”之间二选一；可明确选择“无法确认”，并在获得补充材料后恢复为待确认。

所有核实提示只解释现有规则输出，不生成新的履历事实。后续分析继续只接收用户明确确认的普通事实。

## 2. 用户交互

- 待确认事实提供“正确”“修改”“无法确认”“不参与分析”和“删除”；
- “无法确认”写入 `review.status = uncertain`，可通过“恢复待确认”重新处理；
- 低置信事实显示“请勿直接当作已证实履历”，中置信或缺失关键字段的事实显示补充引导；
- 页面按教育、实习、项目、校园、技能、证书和成果分别提示应核实的字段；
- 时间线提示支持“确认需注意”和“不适用”，处理后保留决定，但不联动事实状态；
- 顶部“不进入分析”数量同时包含 `excluded` 与 `uncertain`。

## 3. 规则与数据边界

核实引导模块版本为 `1.0.0`，根据事实分类、置信度、原因码及已有字段生成：是否需关注、标题、说明、原因和缺失项。模块不修改传入对象，也不会尝试猜测学校、公司、角色、日期、个人贡献或成果归属。

状态边界如下：

| 状态/决定 | 解除待处理阻塞 | 进入分析 | 改变事实内容 |
|---|---:|---:|---:|
| 事实 `confirmed` | 是 | 是 | 否 |
| 事实 `uncertain` | 是 | 否 | 否 |
| 事实 `excluded` | 是 | 否 | 否 |
| 时间线 `confirmed` | 不适用 | 否 | 否 |
| 时间线 `dismissed` | 不适用 | 否 | 否 |

整份确认仍要求：不存在 `pending` 事实，并且至少有一条 `confirmed` 事实。时间线提示属于辅助核实信号，不作为完成阻塞项。
