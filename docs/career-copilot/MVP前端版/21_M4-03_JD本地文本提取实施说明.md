# M4-03 JD 本地文本提取实施说明

> 完成日期：2026-08-13  
> 状态：已完成  
> 范围：可选 JD 输入与结构化提取；不包含简历—JD 差距判断

## 1. 完成结果

用户在目标设置后可以选择粘贴一份 JD，或不提供 JD 直接继续。JD 只在浏览器当前页面中处理，提取职责、硬要求、加分项、任务词、技能词、门槛词和需要进一步核实的招聘表达。

生成页会显示实际提取到的职责和硬要求数量。没有 JD 时明确显示使用通用岗位族规则，不阻塞整个免费诊断流程。

## 2. JdProfile 1.0.0

结构保存：版本、来源字符/行数、职责、必要要求、加分要求、三类关键词、风险提示、区块覆盖状态和生成时间。每个条目保留清洗文本、关键词和原始行号，便于 M4-04 回链。

结构不保存完整 JD 原文；未知字段和版本会由关闭式校验拒绝。

## 3. 提取规则

- 支持岗位职责、工作内容、任职要求、任职资格、加分项、优先条件等常见中文标题；
- 支持 Responsibilities、Required Qualifications、Nice to Have 等英文标题；
- 无标题时根据负责、参与、要求、必须、熟练、学历、经验等行级信号保守分类；
- 任务、技能、门槛词只从显式词典和原文命中，不生成原文不存在的同义词；
- 重复条目按清洗文本去重，保留首次出现的原始行号。

## 4. 风险提示边界

首版提示费用要求、高敏信息要求、与岗位能力可能无关的限制、模糊高薪和过强工作边界。它们只代表“这段表达值得进一步核实”，页面不得作诈骗、违法或歧视的确定性法律判断。

## 5. 页面与隐私

- 输入上限 30,000 字；少于 20 字的非空文本提示补充或跳过；
- 空白输入可直接使用通用岗位族规则；
- JD 原文只保存在当前 React 内存，不写 Web Storage、URL、日志或网络；
- 修改 JD 会清除旧结构和错误；重置流程清除原文、结构与画像分析；
- 功能开关关闭时输入框禁用，并自动采用通用规则。
