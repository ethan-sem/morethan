# M5-01 静态公司岗位 Schema 实施说明

> 完成日期：2026-08-13  
> 范围：纯前端静态数据契约，不接账号、后端、数据库或浏览器抓取  
> Schema：`CompanyRoleKnowledgeBase 1.0.0`

## 1. 本次交付

新增 `src/career-copilot/domain/companyRoleKnowledgeBase.js`，为静态公司岗位知识库提供关闭式、版本化的数据契约和纯函数校验器；新增 `public/data/career-copilot/company-role-pool.json` 作为可直接随静态站点构建发布的数据文件。

数据包当前是刻意保持为空的 `draft`。M5-01 只定义结构和可信度边界，不提前放入示例公司、虚构职位或未经核验的“在招”状态。实际公开来源白名单由 M5-02 建立，首批 30 家公司由 M5-03 填充。

## 2. 数据模型

根数据包包含：

| 区块 | 用途 | 关键字段 |
|---|---|---|
| 数据集元信息 | 版本、发布与整体时效 | `schemaVersion`、`datasetVersion`、`status`、`publishedAt`、`validThrough` |
| `tagDefinitions` | 统一行业、地点、项目等标签 | `id`、`label`、`category` |
| `companies` | 公司主数据 | 稳定 ID、名称、别名、组织类型、官网、标签 |
| `roleFamilies` | 岗位族主数据 | 稳定 ID、名称、别名、父岗位族、标签 |
| `sources` | 可追溯公开资料 | 来源类型、标题、发布方、URL、抓取/核验/到期时间、使用口径、许可备注 |
| `recruitmentEntrances` | 实习/校招申请入口 | 公司、招聘类型、URL、来源、状态、三类时间、标签 |
| `records` | 公司 × 岗位族记录 | 岗位名、地点、招聘类型、状态、入口/来源、三类时间、证据要求、顾问备注、复核状态 |

所有实体使用小写 kebab-case 稳定 ID。岗位记录通过 ID 关联公司、岗位族、来源、入口和标签，避免复制名称后产生不一致。

## 3. 可信度与安全规则

1. 来源和入口只接受 HTTPS 链接。
2. 抓取时间使用 UTC ISO 时间戳；核验日和到期日使用 `YYYY-MM-DD`，且必须满足“抓取 ≤ 核验 ≤ 到期”。
3. `open` 岗位或 `active` 入口必须至少绑定一种实时状态来源：公司招聘官网、公司官方页面或明确授权招聘来源。
4. 政府、高校和其他公开资料可以形成公司/岗位方向参考，但不能单独证明岗位当前在招。
5. 每条公司岗位记录必须至少绑定一个公开来源；未知引用、重复 ID、重复来源 URL 和未定义标签均报错。
6. 发布数据必须有发布时间、整体有效期和至少一条已完成顾问复核的岗位记录；空白草稿仍可安全构建。
7. Schema 不允许公司永久档次、录取概率、成功率等字段。四层投递建议继续由用户证据与具体岗位规则实时决定。
8. 本契约不做联网抓取，也不根据运行当天自动删除过期数据。构建期过期阻断属于 M5-05，页面降级展示属于 M5-06。

## 4. 验证覆盖

新增 8 项契约测试，覆盖：

- 空白草稿与随站点发布的 JSON 包一致且有效；
- 完整公司—岗位族—来源—入口—岗位关联；
- 未知字段、永久档次和成功率字段拒绝；
- HTTPS 与三类时间顺序；
- 悬空公司、岗位族、来源和标签引用；
- 非官方公开来源不得单独声明实时在招；
- 入口与岗位的公司、招聘类型一致性；
- 发布日期、非空记录和顾问复核门槛。

完整质量检查通过：lint、严格 JSDoc 类型检查、34 个测试文件共 205 项测试、PDF/DOCX 解析依赖构建探针和生产构建均通过。生产主包为 403.33 kB，gzip 后 125.57 kB；样式为 81.34 kB，gzip 后 15.79 kB。本任务未把校验器引入页面主包，因此主包无实质增长。
