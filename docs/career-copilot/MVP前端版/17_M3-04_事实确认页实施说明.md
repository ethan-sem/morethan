# M3-04 事实确认页实施说明

> 完成日期：2026-08-10  
> 状态：已完成  
> 数据契约：`ResumeFacts 1.0.0`

## 1. 目标与结果

M3-04 用真实本地提取结果替换了事实页示例数据。用户可以逐条查看结构化事实、遮罩后的原文证据、来源章节/PDF 页码、识别置信度和确认状态，并完成确认、修改、排除、删除与新增。

只有所有事实完成处理且至少一条事实被明确确认后，用户才能进入求职目标和后续分析。当前功能完全运行在浏览器内存中，没有账号、后端、数据库、上传或持久化。

## 2. 页面结构

事实确认页包含：

1. 全部事实、已确认、待处理、不进入分析四项进度；
2. 日期缺失、无效、冲突和重叠提示；
3. 教育、实习、项目、校园、技能、证书、成果/奖项七个事实分组；
4. 每条事实的摘要、来源片段、章节/页码、置信度和确认状态；
5. 确认、排除、恢复、修改、删除操作；
6. 新增事实表单；
7. 受状态约束的“完成事实确认”按钮。

材料没有成功读取时，事实页不再使用示例数据。材料页的下一步按钮保持禁用，避免用户绕过真实事实流程。

## 3. 状态规则

| 状态 | 用户含义 | 是否进入分析 |
|---|---|---|
| `pending` | 尚未确认，或刚刚新增/修改 | 否 |
| `confirmed` | 用户明确确认正确 | 是 |
| `excluded` | 用户选择不参与本次分析 | 否 |
| `uncertain` | 无法确认；M3-05 已提供专门入口 | 否 |

确认和排除都会记录 UTC 更新时间。排除事实可以恢复为待确认。修改任何事实都会将其来源类型改为 `user_edited` 并重置为 `pending`，防止已确认结论在内容改变后继续生效。

整份确认完成时，根状态变为 `completed`；后续任何编辑、增删或状态变化都会重新变为 `in_progress`。

## 4. 修改与新增

编辑表单按事实类型提供结构化字段：

- 教育：院校、学历、专业、起止日期和亮点；
- 实习：组织、岗位、地点、日期、动作、方法、结果和指标；
- 项目：名称、角色、日期、动作、方法、结果、指标和工具；
- 校园：组织、职务、日期、动作和结果；
- 技能：名称、熟练度和关键词；
- 证书：名称、颁发方、获得/过期日期和凭证编号；
- 成果：标题、颁发方、日期、级别和说明。

日期支持 `YYYY`、`YYYY-MM` 和 `YYYY-MM-DD`，也支持“仍在进行中”。无效日期在保存前拦截。

新增事实使用独立稳定 ID，来源类型为 `user_added`，不创建虚假 `sourceRef`。用户必须填写该类型的核心名称或组织信息，不能保存完全空白事实。

## 5. 删除与引用完整性

删除采用页面内二次确认，不调用浏览器阻塞弹窗。删除后：

- 事实从当前内存对象移除；
- 只引用该事实的时间线提示被移除；
- 多事实提示保留剩余有效引用；
- 技能事实里的证据 ID 同步清除；
- 完整结构重新通过关闭式校验。

因此删除不会留下悬空引用，也不会影响原始简历正文；用户仍可返回材料页重新读取并恢复原始提取结果。

## 6. 来源与隐私

原文片段不存入事实对象。页面使用 `sourceRefs` 从内存正文即时读取，最多显示 320 个字符，并再次应用 M3-02 敏感字段遮罩。姓名、电话、邮箱、身份证号和详细地址不会因来源回链重新暴露。

用户新增事实显示“用户手动新增，无原文来源”，与规则提取事实明确区分。刷新、关闭页面或执行清除后，正文与所有编辑结果都会消失。

## 7. 分析准入门槛

“完成事实确认”按钮需要同时满足：

- `pending = 0`；
- `confirmed > 0`。

完成后仍由既有 `selectConfirmedFacts()` 提供后续分析输入。该选择器只返回 `confirmed` 普通事实，自动排除 `pending`、`excluded`、`uncertain` 和全部敏感字段。这是 MFR-023 的代码级边界，而非仅靠页面文案约束。
