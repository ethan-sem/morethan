# M7-02 自动化质量闭环实施说明

> 状态：已实施  
> 范围：本地解析、事实与规则引擎、报告生成、隐私和一键清除

## 1. 目标

在原有模块单元测试基础上，增加一套使用 M7-01 纯虚构材料的发布级自动化闭环，验证同一份材料能够从输入经过事实确认和规则分析，稳定生成带边界的报告，并可彻底清除。

M7-02 不替代 M7-03 的真实浏览器兼容测试，也不替代 M7-04 的无障碍、响应式和打印视觉检查。

## 2. 新增发布级测试层

### 2.1 纯虚构样本管线

9 份可分析简历逐份经过：

```text
虚构文本
→ 敏感字段识别
→ ResumeFacts 提取
→ 全部事实模拟用户确认
→ 时间提示模拟用户处理
→ 方向与证据分析
→ 证据不足降级
→ 四层投递组合
→ 48 小时 / 7 天 / 30 天行动计划
→ 结论来源标记
```

每份样本验证：

- 分析只消费已确认事实；
- 优势和短板不超过各 3 项；
- 行动计划为 3–5 项并覆盖三个时间窗；
- 降级、四层、行动和来源契约均通过关闭式校验；
- 输出结构不增加录取概率、成功率或保证字段。

### 2.2 完整报告管线

跨专业产品样本和产品 JD 继续经过：

```text
ResumeFacts
→ 方向分析
→ JdProfile
→ 简历—JD 差距
→ 四层策略
→ 行动计划
→ 来源索引
→ 带官方来源公司目标池
→ 脱敏纯文本报告
```

验证报告包含 JD 对照、公司目标池、生成方式和非录用保证；所有公司条目必须带 HTTPS 来源与核验日期；原始样本标记不进入导出报告。

### 2.3 保守低匹配场景

跨专业产品简历与量化研究 JD 组合验证：

- 产生多个“未找到证据”和硬要求缺口；
- 明确“未找到不等于不具备”；
- 明确不代表录取概率或录用保证；
- 结构中不出现概率、成功率或保证字段。

### 2.4 隐私链路

联系方式密集、表格式简历验证：

- 邮箱和电话被本地识别；
- 原值不进入结构化事实；
- 原值不进入脱敏导出报告。

## 3. 程序生成的异常材料

新增完全在测试内存中生成的二进制资产，不从真实简历改造，也不写入仓库文件：

| 材料 | 自动化预期 |
|---|---|
| 最小文本 PDF | 文件签名通过，PDF.js 可提取正文 |
| 无文本层 PDF | 识别为扫描型材料，要求粘贴/手填替代 |
| 加密 DOCX 容器 | 在加载 Mammoth 前识别为受保护文件 |
| 损坏 DOCX | 固定错误码，不泄露底层路径或错误详情 |
| 虚拟 10MB+ 文件 | 读取前拒绝，不分配或读取超大正文 |

## 4. 既有界面闭环

发布测试套件同时保留真实 React 页面用例：

- 用户从粘贴简历到事实确认、方向、JD、报告、复制、打印和行动计划；
- 未导出离开提醒；
- 一键清除的二次确认、内存复位、命名空间数据清理和返回开始页。

## 5. 自动化入口

- `pnpm run test:release`：运行发布关键路径测试；
- `pnpm run test:run -- --maxWorkers=1 --no-file-parallelism`：运行全部自动化测试；
- `pnpm run check`：完整代码、测试、解析依赖及生产构建检查。

发布关键路径套件固定单 Worker，降低桌面环境并行线程启动波动，不改变业务逻辑。

## 7. 仍需人工或真实浏览器验证

- Chrome、Edge、Safari 最近两个主版本；
- 375px 移动端真实交互；
- 键盘焦点顺序和屏幕阅读器语义；
- 浏览器打印预览和 PDF 分页视觉；
- 5MB 真实文本型文档性能及连续三轮内存观测；
- 生产环境网络面板、CSP 与缓存头。

以上分别进入 M7-03 至 M7-07，不应被自动化测试通过所替代。

## 8. 验收标准

- M7-01 纯虚构样本可贯穿分析和报告管线；
- 异常 PDF / DOCX / 超限材料由程序生成并产生固定安全结果；
- 页面完整流程和一键清除继续通过；
- 发布关键路径拥有独立脚本；
- lint、类型检查、全量自动化测试、三类构建门禁、解析探针和生产构建全部通过。

- lint 与 TypeScript 检查：通过；
- 静态数据、匿名样本及隐私门禁：通过；
- PDF / DOCX 解析依赖探针：通过；
- Vite 生产构建：通过。
