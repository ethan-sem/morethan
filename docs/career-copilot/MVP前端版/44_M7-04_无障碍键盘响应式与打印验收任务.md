## 1. 任务目标

验证并修复智能求职助手在以下四个方面的发布阻断问题：

1. 用户不依赖鼠标也能完成核心求职诊断流程；
2. 页面结构、控件名称、状态反馈和焦点管理可被辅助技术理解；
3. 320px 至桌面宽屏及 200% 缩放下不存在关键内容丢失、遮挡或横向溢出；
4. 浏览器打印或另存 PDF 后，报告完整、清晰、脱敏且不包含网页操作控件。

本任务是上线质量验收，不新增业务模块，也不改变“纯前端、无账号、无后端、免费且功能不阉割”的 MVP 范围。

## 2. 验收范围

### 2.1 必测页面与流程

- 开始页与官网返回入口；
- 简历文件选择、文本粘贴和手工填写；
- 本地解析进度、成功、失败和取消状态；
- 简历事实新增、编辑、确认、排除与时间冲突处理；
- 求职阶段、方向和可选 JD 输入；
- 证据不足追问与无 JD 降级流程；
- 生成中状态、完整报告、证据展开区和公司官方入口；
- 行动计划的展开、标记完成与长页面导航；
- 数据与设置、一键清除确认弹窗；
- 复制纯文本、浏览器打印与保存 PDF。

### 2.2 不在本任务内

- 账号、登录、云端历史报告和跨设备同步；
- 新增生成式 AI 或服务端接口；
- 对全站品牌页面进行整体视觉重构；
- 为扫描 PDF 增加 OCR；
- 第三方机构出具的无障碍合规认证。

## 3. 无障碍检查

### 3.1 页面结构与可访问名称

- 每个流程页面只有一个清晰的一级标题；
- `main`、导航、章节、表单、列表和弹窗使用与含义相符的原生元素或 ARIA 角色；
- 所有输入框、文件选择、按钮、链接、折叠区和图标按钮均有唯一且可理解的名称；
- 装饰图标不进入辅助技术阅读顺序；
- 错误信息与对应输入建立关联，不能只依赖红色表达错误；
- 解析进度、复制结果、生成状态和清除结果使用适度的 `status`、`alert` 或 `aria-live`；
- 当前步骤、当前标签页、开关和完成状态能通过语义属性读取；
- 新窗口打开的官方招聘链接应在文字或可访问名称中提供合理预期。

### 3.2 视觉可辨识性

- 正文与背景达到 WCAG AA 普通文本对比度目标 4.5:1；
- 大号文本达到 3:1；
- 输入边界、焦点指示和有意义的非文本图形达到 3:1；
- 任何状态均不能只用颜色区分，必须同时有文字、图标或结构差异；
- 键盘焦点在浅色、深色和警告背景上均清楚可见；
- 系统启用减少动态效果时，关闭非必要动画并保留状态反馈；
- Windows 高对比度/强制颜色模式下，主要按钮、表单和焦点不消失。

### 3.3 辅助技术抽查

- Windows 至少使用一种桌面屏幕阅读器完成开始页、材料页、报告页和清除弹窗抽查；
- Safari 实机验收时补充 VoiceOver 抽查；
- 阅读顺序与视觉顺序一致；
- 标题、区域、表单标签、错误、状态变化和弹窗名称均可理解；
- 不出现无名称按钮、重复朗读、焦点落入隐藏内容或弹窗背景仍可操作的问题。

屏幕阅读器未实际运行时，只能记录为待人工复核，不能以静态代码检查代替。

## 4. 键盘操作检查

### 4.1 通用规则

- 使用 `Tab` 和 `Shift+Tab` 能按视觉与任务顺序遍历所有可操作控件；
- 按钮可用 `Enter` 或 `Space` 操作，链接可用 `Enter` 打开；
- 原生折叠区可用键盘展开和收起；
- 不存在正向 `tabindex`、键盘陷阱或需要鼠标悬停才能获得的信息；
- 禁用控件不会被误认为可操作，禁用原因在上下文中清楚可见；
- 步骤切换后，焦点移动到新页面标题或合理的起始位置；
- 长页面进入下一步骤后不能保留在旧页面底部。

### 4.2 特殊组件

- “粘贴完整简历/手工填写”标签页支持左右方向键、`Home` 和 `End`，且只有当前标签进入 Tab 顺序；
- 文件选择区域可通过键盘触发原生文件选择器，并显示可见焦点；
- 事实编辑、确认、排除和新增操作不会导致焦点丢失；
- 错误发生后焦点或状态播报能引导用户找到错误；
- 清除数据弹窗打开后焦点进入弹窗，`Tab` 不离开弹窗，`Escape` 可取消，关闭后焦点回到触发按钮；
- 正在执行不可逆清除时，不允许重复提交或误用 `Escape` 中断已开始的清理；
- 行动计划长页面可只用键盘进入“数据与设置”。

## 5. 响应式与缩放检查

### 5.1 视口矩阵

| 类型 | 视口 | 重点 |
|---|---:|---|
| 最小支持宽度 | 320×568 | 无横向滚动、表单和弹窗可用 |
| 主流窄屏 | 375×812 | 完整主流程、触控目标、报告阅读 |
| 大屏手机 | 390×844 | 输入法弹起前后的底部操作区 |
| 平板竖屏 | 768×1024 | 双栏降级、卡片与表格重排 |
| 小型桌面 | 1024×768 | 导航、长页面和弹窗 |
| 标准桌面 | 1440×900 | 默认版式和报告信息密度 |

### 5.2 验收规则

- 页面 `scrollWidth` 不超过可视宽度；代码、URL 和长英文词可安全换行；
- 主操作、错误提示、免责声明和清除入口不被固定元素遮挡；
- 可操作目标满足 WCAG 2.2 AA 最低 24×24 CSS px，并优先保持现有 32px 以上目标；
- 竖屏和横屏切换后，不丢失输入内容或当前流程状态；
- 浏览器 200% 缩放以及等效 320px 重排下，核心内容与操作仍可访问；
- 移动端软键盘出现时，当前输入和提交操作可滚动到可见区域；
- 报告卡片、证据展开区、公司链接和行动步骤不发生重叠、截断或错序。

## 6. 打印与保存 PDF 检查

### 6.1 内容完整性

打印版必须保留：

- 报告标题、生成日期或版本信息；
- 摘要、方向、核心优势、主要短板；
- JD 差距（用户提供 JD 时）；
- 四层投递组合与公司目标池；
- 48 小时、7 天、30 天行动计划；
- 结论来源、公开资料核验日期、时效提示；
- 本地规则生成、非录用保证和隐私边界。

打印版必须隐藏：

- 官网导航、流程进度、返回和下一步按钮；
- 复制、打印、编辑、完成勾选等网页操作控件；
- 浮动提醒、背景装饰和确认弹窗；
- 原始简历正文、未脱敏联系方式和临时 API 密钥。

### 6.2 版式要求

- 默认 A4 纵向打印，页边距合理；
- 标题不孤立在页底，关键卡片尽量避免跨页断裂；
- 多页报告不发生内容重叠、裁切、空白首页或末页大面积异常空白；
- 深色卡片在彩色和黑白打印下均可阅读；
- 长 URL 可换行，来源名称和核验日期仍可辨认；
- 保存后的 PDF 可选择文本，中文不乱码；
- Chrome/Edge 至少完成一次真实打印预览和另存 PDF；Safari 打印纳入 M7-03 实机补验。

## 7. 自动化与静态门禁

应补充最小但有效的回归检查：

- 标签页方向键与 ARIA 关联；
- 步骤切换后的标题焦点；
- 清除弹窗的初始焦点、焦点圈定、`Escape` 和焦点归还；
- 关键表单的标签、错误关联和状态区域；
- 禁止正向 `tabindex`、无名称图标按钮及 `target="_blank"` 缺少安全属性；
- 样式必须保留 `:focus-visible`、`prefers-reduced-motion`、强制颜色和 `@media print` 规则；
- 生产构建继续执行现有隐私、匿名样本、数据和浏览器兼容门禁。

自动化只负责防止已修复问题回归，不替代屏幕阅读器、移动设备和打印预览实测。

## 8. 缺陷等级

| 等级 | 定义 | 示例 | 发布处理 |
|---|---|---|---|
| P0 | 核心流程无法完成或泄露敏感信息 | 键盘无法提交、打印出现原始手机号 | 必须立即修复，禁止发布 |
| P1 | 关键内容不可理解或严重影响一类用户 | 弹窗焦点逃逸、报告在 375px 被截断 | M7-04 结束前必须修复 |
| P2 | 有替代路径但体验明显受损 | 次要状态未播报、局部换行不佳 | 记录并尽量在 M7-07 前关闭 |
| P3 | 不影响任务完成的细节 | 非关键间距或打印分页偏好 | 可进入后续优化池 |
