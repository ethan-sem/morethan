# M2-02 PDF 浏览器本地解析实施说明

> 完成日期：2026-08-09  
> 状态：已实现并通过自动测试与生产构建  
> 解析范围：带文本层的 PDF；不包含 OCR

## 1. 已实现能力

- 用户选择 PDF 后，在浏览器内将 `File` 转为独立 `Uint8Array`；
- 按需加载 PDF.js Display API 和同版本 Worker；
- 逐页调用 `getTextContent()`，重建段落、换行和英文词间空格；
- 返回页数、有文本页数、非空白字符数、逐页文本及警告；
- 页面显示解析进度、摘要和最多 360 字的本地文本预览；
- 低于最小文本阈值时识别为无可用文本层，明确提示扫描件暂不支持 OCR；
- 支持停止旧解析任务，重新选择或重置时不保留旧结果；
- 解析结果仅保存在 React 内存状态，不进入 sessionStorage、localStorage、URL 或日志；
- 无论成功或失败都会销毁 PDF.js 加载任务和 Worker 引用。

## 2. 结果结构

```text
PdfParseResult
├─ text              合并后的全文
├─ pageCount         PDF 总页数
├─ textPageCount     检测到文字的页数
├─ characterCount    非空白字符数
├─ pages[]           pageNumber + text
└─ warnings[]        无文字页面等非阻断问题
```

M3 事实提取应消费 `text` 和 `pages`，不得重新读取原始文件。

## 3. 当前错误码

| 错误码 | 用户结果 |
|---|---|
| `PDF_NO_TEXT_LAYER` | 提示可能为扫描版，当前不支持 OCR |
| `PDF_PASSWORD_REQUIRED` | 提示先解除密码 |
| `PDF_INVALID` | 提示文件可能损坏 |
| `PDF_EMPTY_FILE` | 提示重新导出 |
| `PDF_ABORTED` | 静默停止旧任务或显示已停止 |
| `PDF_PARSE_FAILED` | 提供重新导出文本型 PDF 的恢复建议 |
| `PDF_UNSUPPORTED_INPUT` | 拒绝非本地二进制输入 |

文件类型、大小、加密和损坏文件的前置校验及文案已由 M2-05 统一完成。

## 4. 安全控制

- `getDocument` 只收到 `data`，不传入 `url`，因此解析器没有远程 PDF 获取路径；
- 使用已经修复 `CVE-2026-16633` 的 `pdfjs-dist@6.2.108`；
- 明确传入 `enableScripting: false`、`enableXfa: false`、`useWorkerFetch: false` 和 `useWasm: false`；
- 不创建 PDF Viewer、注释层、表单层或脚本管理器；
- 不读取或执行 PDF JavaScript、附件、外部链接和表单动作；
- 错误对象只映射为内部错误码和固定文案，不把底层错误消息、文件名或正文展示/记录。

## 5. 文本重建规则

- PDF.js 标记 `hasEOL` 时结束当前行；
- 文本项 Y 坐标出现显著变化时开始新行；
- 英文数字相邻项按坐标间距补空格；
- 中文连续字形默认不插入空格；
- 页面间使用空行分隔；
- 空文本页记录警告，不影响其他有效页面；
- 全文不足 24 个非空白字符时降级为无可用文本层。

该规则只提供可靠的基础文本顺序。复杂双栏、浮动文本框和特殊字体的进一步校准将在真实匿名样本测试中迭代。
