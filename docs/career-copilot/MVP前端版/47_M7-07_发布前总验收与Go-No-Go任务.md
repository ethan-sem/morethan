# M7-07 发布前总验收与 Go/No-Go 任务

> 文档状态：已执行，待外部证据与责任角色签字  
> 任务状态：`[review]`  
> 适用版本：MoreThan 智能求职助手 MVP 前端版  
> 上位文档：`05_MVP验收与上线方案.md`  
> 任务边界：形成可发布结论和证据包，不执行 M7-08 正式生产发布

> 2026-08-20 执行结果：冻结 `MoreThan-Career-Copilot-MVP-FE-v1.0.0-rc.1`；本地完整门禁、10/10 匿名报告机器预检及两项回滚演练通过；因外部浏览器/实机、读屏与真实打印、内容顾问及管理层签字缺失，最终结论为 `NO-GO`。实施原始记录见 `51_M7-07_发布前总验收与Go-No-Go记录.md`。

## 1. 任务目标

冻结一个唯一的发布候选版本，对产品功能、报告内容、浏览器兼容、无障碍、性能、安全、静态知识数据、隐私声明和回滚能力执行最终验收，形成管理层可以直接作出决定的发布证据包。

M7-07 必须回答四个问题：

1. 当前候选版本是否实现了约定的纯前端 MVP 完整流程；
2. 是否存在会伤害用户、泄露材料、误导求职决策或阻断核心流程的风险；
3. 如果生产发布失败，是否有经过验证的快速回滚或功能降级路径；
4. 管理层是否明确批准将这个未经变更的候选产物交给 M7-08 发布。

本任务的结果只能是：`GO`、`CONDITIONAL GO` 或 `NO-GO`。不能使用“应该没问题”“基本通过”等无法执行的结论。

## 2. 与 M7-08 的边界

M7-07 可以：

- 生成和验证本地或受控预览环境的发布候选产物；
- 完成真实浏览器、设备、打印、网络、存储和安全头检查；
- 准备发布清单、版本摘要、回滚包和生产冒烟步骤；
- 提交管理层签字并给出 Go/No-Go 建议。

M7-07 不可以：

- 未经用户明确授权部署到官网生产环境；
- 修改生产域名、DNS、CDN 或正式托管配置；
- 向真实用户开放入口；
- 把 `CONDITIONAL GO` 自动视为生产发布授权；
- 在验收完成后手工替换发布包内的文件。

正式发布只属于 M7-08，并必须再次获得用户明确指令。

开始 M7-07 前应满足：

- M7-01 匿名化测试样本集为 `[done]`；
- M7-02 自动化质量闭环为 `[done]`；
- M7-03 的 Chrome、Edge、Safari、iOS Safari 和 Android Chrome 必测项已完成，或每个未完成项均有明确阻断说明；
- M7-04 无障碍、键盘、响应式与打印验收完成；
- M7-05 性能优化与资源预算门禁完成；
- M7-06 安全、隐私与供应链检查完成；
- M5 公司岗位数据完成当期复核，无阻断性过期记录；
- 产品范围、规则版本、披露文案和功能开关已冻结；
- 不存在未确认归属的代码、数据或构建配置变更。

若 M7-03 至 M7-06 仍有 `[todo]` 或未解释的 `[review]`，M7-07 可以建立验收准备清单，但不能给出 `GO`。

## 4. 发布候选版本冻结

### 4.1 候选版本标识

每个候选版本使用唯一标识，例如：

```text
MoreThan-Career-Copilot-MVP-FE-v1.0.0-rc.1
```

候选清单必须记录：

- 产品版本和候选序号；
- 构建日期、时区和执行人；
- Git commit、归档摘要或等效不可变版本标识；
- 锁文件 SHA-256；
- 生产构建目录 SHA-256 清单；
- `ResumeFacts`、分析规则、报告披露和公司数据 Schema 版本；
- 公司岗位池、岗位族映射和来源白名单数据版本；
- 功能开关最终值，特别是 BYOK 必须默认关闭；
- 浏览器兼容目标和已知限制；
- 对应的测试、性能和安全证据目录。

### 4.2 冻结规则

候选版本进入总验收后：

- 禁止顺手优化文案、样式、依赖或数据；
- 任何代码、CSS、静态数据、依赖、环境变量或托管头变更都必须生成新的候选序号；
- P0/P1 修复后执行完整受影响回归，不得沿用旧签字；
- 仅更新验收记录、不改变产物时无需重建；
- M7-08 必须发布与最终签字摘要完全一致的构建产物。

## 5. 验收角色与签字责任

| 角色 | 主要责任 | 必须签字内容 |
|---|---|---|
| 产品负责人 | MVP 范围、核心流程、披露和已知限制 | 功能与产品边界 |
| 技术负责人 | 构建、架构、回滚、依赖和发布包 | 技术发布就绪 |
| 测试负责人 | 用例、浏览器矩阵、缺陷和复测 | 质量结论 |
| 内容顾问 | 规则阈值、四层建议、公司资料和行动建议 | 内容准确性与边界 |
| 隐私/安全负责人 | 网络、存储、密钥、CSP、日志和依赖风险 | 安全发布结论 |
| 发布负责人 | 候选版本、发布步骤、冒烟与回滚卡 | 可操作性 |
| 管理层批准人 | 风险接受与最终 Go/No-Go | 是否允许进入 M7-08 |

小团队允许一人承担多个角色，但内容数据的编辑与复核仍应遵循 M5-07 的职责分离；同一人不能独自编辑、复核并批准同一批公司岗位数据。

## 7. 功能发布门禁

以下为不可缺失的 P0 流程：

1. 官网一级入口可进入助手，无需登录；
2. PDF、DOCX、TXT、粘贴和手工填写有可用或明确不支持结果；
3. 扫描 PDF、加密/损坏文件、空白和超限材料安全降级；
4. 用户可以查看、编辑、确认、排除和补充简历事实；
5. 未处理完事实不能进入分析；
6. 可选择实习/校招阶段和六个首发方向；
7. 无 JD 时生成方向级报告并明确边界；
8. 有 JD 时生成要求拆解、证据匹配、缺口与行动；
9. 证据不足时追问、条件化或省略，不编造事实；
10. 报告包含摘要、优势、短板、方向、四层、公司目标、行动和免责声明；
11. 关键结论可追溯到已确认事实、规则或公开资料；
12. 公司入口显示来源、核验日期和过期状态；
13. 复制脱敏文本和打印 PDF 可用；
14. 行动计划可展开、标记完成并进入设置；
15. 一键清除后返回开始页且数据不可恢复；
16. 刷新、返回、重复生成和异常恢复没有死页。

## 8. 内容顾问验收

### 8.1 抽检样本

至少抽检 10 份匿名报告，覆盖：

- 六个首发岗位方向；
- 理工科两段相关实习；
- 商科项目多但量化不足；
- 跨专业转产品/运营；
- 大一/大二经历较少；
- 中文、英文和中英混合材料；
- 时间线冲突与联系方式密集；
- 高匹配和低匹配 JD；
- 无 JD 降级；
- 公司公开资料过期降级。

### 8.2 内容检查标准

内容顾问逐份确认：

- 不编造教育、经历、技能、结果和在招状态；
- 优势与短板有证据且表述克制；
- 不使用学校层级、性别、年龄等敏感属性进行价值判断；
- 不输出录取概率、保实习、保 offer 或确定性承诺；
- 四层只是本次投递组合，不是公司永久档次；
- JD 缺口只表示简历证据情况，不断言用户实际不会某技能；
- 行动建议真实、可执行、带产出物和完成标准；
- 公司入口和公开资料来源可信、日期清楚；
- 证据不足时追问或降级，不用流畅文案掩盖缺口；
- 隐私、生成方式、资料时效和非录用保证声明明显且一致。

抽检发现系统性误导时，应停止签字并回到规则或报告任务修复，不能只改单个示例报告。

## 9. 浏览器与设备验收

### 9.1 最低矩阵

| 平台 | 必测内容 |
|---|---|
| Chrome / Windows | 全流程、PDF/DOCX、复制、打印、清除、网络与存储 |
| Edge / Windows | 同上 |
| Safari / macOS | Worker、文件解析、Clipboard、打印、离开提醒 |
| Safari / iOS | 375/390px 输入、滚动、报告、外链、清除 |
| Chrome / Android | 文本输入、触控、报告、外链、清除 |

记录浏览器版本、系统版本、设备、视口、日期、测试人和结果。模拟视口不能代替 iOS/Android 实机签字。

### 9.2 体验与无障碍

- 核心流程可只使用键盘完成；
- 焦点、标签、错误和状态可感知；
- 至少一种桌面屏幕阅读器完成规定抽查；
- 320px 至 1440px 和 200% 缩放无阻断；
- 375px 移动端无横向溢出、遮挡或不可点击控件；
- 打印版内容完整、无操作控件、无敏感原文；
- 长行动页面可正常进入设置，步骤切换后焦点与滚动位置合理。

## 10. 性能与稳定性验收

- 官网首页不下载助手完整业务代码；
- 粘贴/手填不下载 PDF.js 或 Mammoth；
- PDF 与 DOCX 只加载对应解析资源；
- 公司岗位数据在报告阶段按方向加载；
- 资源体积通过 M7-05 构建预算；
- LCP、CLS、交互延迟达到 M7-05 实验室目标；
- 解析状态及时出现，解析期间页面保持响应；
- 5MB 目标样本可完成解析；
- 连续生成三次报告并清除，不出现明显持续内存增长；
- 动态模块、静态数据或 Worker 加载失败时有独立降级和重试；
- 性能优化未改变事实、分析、来源、打印和清除结果。

## 11. 安全与隐私验收

- 源码、环境模板和最终构建产物无真实秘密；
- 完整流程网络请求中无简历、JD、事实、报告或密钥；
- 浏览器持久化只包含允许的无敏感流程位置；
- PDF/DOCX/TXT 恶意内容不执行代码；
- XSS、危险协议、远程脚本和非白名单网络调用被阻止；
- CSP 和安全响应头在生产等效环境生效；
- 外链为 HTTPS、带隔离属性且不附加用户参数；
- 日志、错误、复制和打印完成脱敏；
- BYOK 默认关闭，启用实验时密钥仅内存并可销毁；
- Critical/High 生产依赖风险为 0 或符合不可豁免规则；
- 发布目录无环境文件、测试材料、内部草稿、日志、source map 和本机路径；
- 安全门禁已完成故意违规样本的反向失败验证。

## 12. 已知限制验收

页面、报告和发布说明必须一致披露：

- 当前只服务实习/校招，不覆盖 1–3 年社招；
- 当前没有账号、云端档案和历史报告；
- 扫描型 PDF 暂不提供 OCR，可改用粘贴或手填；
- 当前正式能力由浏览器本地确定性规则生成，不等同于生成式 AI 顾问；
- 公司资料是带来源和核验日期的目标池，不代表实时在招或录用保证；
- 四层建议是本次投递组合，不是公司永久评级；
- 用户需要自行管理已复制到剪贴板或保存到设备的 PDF；
- 刷新或关闭页面后，本次材料和未导出报告不再保留。

如果产品页面、打印报告、帮助文案和管理层说明对同一限制表述冲突，视为 P1。

## 13. 回滚与降级演练

### 13.1 回滚准备

- 保留当前官网上一稳定生产构建；
- 记录上一稳定版本摘要、存放位置和恢复步骤；
- 准备本次候选构建完整摘要，确保能区分新旧版本；
- 明确发布负责人、回滚批准人和最长决策时间；
- 回滚不依赖数据库迁移，因为 MVP 不保存服务端用户数据；
- 验证恢复旧构建后官网其他页面仍可用。

### 13.2 功能降级卡

| 故障 | 首选动作 | 保留能力 |
|---|---|---|
| PDF 解析异常 | 关闭 PDF 解析功能开关 | DOCX、TXT、粘贴、手填 |
| DOCX 解析异常 | 关闭 DOCX 相关入口或提示 | PDF、TXT、粘贴、手填 |
| 公司数据失效 | 隐藏具体公司目标池 | 岗位族、四层方法、个人报告 |
| 规则严重误导 | 暂停真实报告生成 | 维护提示与材料清除 |
| 助手影响官网 | 移除一级入口并回滚构建 | MoreThan 官网其他功能 |
| 安全或隐私风险 | 立即下线助手并回滚 | 官网静态品牌内容 |

M7-07 至少在非生产环境演练一次“助手入口回退”和一种功能开关降级，并记录实际步骤、耗时和结果。

## 14. 缺陷与风险处置

### 14.1 缺陷等级

| 等级 | 定义 | M7-07 处理 |
|---|---|---|
| P0 | 核心流程阻断、用户材料/秘密泄露、代码执行、严重误导 | 不可豁免，结论必须为 `NO-GO` |
| P1 | 关键兼容、无障碍、性能、安全、内容或回滚缺陷 | 默认阻断；仅有限类别允许管理层书面接受 |
| P2 | 有替代路径、影响有限且不触碰隐私/安全底线 | 可带负责人和期限进入发布后修复 |
| P3 | 不影响任务完成的细节 | 记录到优化池 |

### 14.2 不可豁免项

以下即使标为 P1 也不得 `CONDITIONAL GO`：

- 任何真实密钥或用户材料外泄；
- 简历/JD/报告非预期网络发送或持久化；
- 可执行 XSS、恶意文件代码或高危供应链路径；
- 无法清除本次数据；
- 报告编造用户事实、录取保证或系统性歧视判断；
- 官网或助手核心流程在目标浏览器普遍不可用；
- 没有可操作的回滚包或候选版本无法唯一识别。

### 14.3 风险接受记录

可接受风险必须记录：

- 缺陷 ID、现象、影响范围和复现步骤；
- 为什么不影响 P0 和隐私/安全底线；
- 临时替代路径或降级提示；
- 负责人、修复日期和验证人；
- 产品、技术和管理层批准；
- 超期后的自动升级或下线条件。

口头同意、聊天截图或没有到期日的“后续优化”不构成有效风险接受。

## 15. Go/No-Go 规则

### 15.1 GO

同时满足：

- 所有 P0 通过；
- P1 为 0；
- M7-01 至 M7-06 的必需证据完整；
- 10 份报告内容抽检签字完成；
- 浏览器/移动设备矩阵满足要求；
- 发布包和回滚包摘要已确认；
- 所有必须角色签字。

### 15.2 CONDITIONAL GO

仅在以下条件下允许：

- P0 为 0；
- 不存在不可豁免 P1；
- 剩余问题有明确且可用的替代路径；
- 风险接受记录完整；
- 管理层明确批准带风险进入 M7-08；
- 已定义触发回滚或下线的阈值。

### 15.3 NO-GO

出现任一情况即为 `NO-GO`：

- 任一 P0 未关闭；
- 存在不可豁免 P1；
- 必测浏览器或安全/隐私证据缺失；
- 内容顾问拒绝签字；
- 候选版本在验收中被修改但未重新构建；
- 回滚未准备或未演练；
- 管理层未给出明确批准。

`NO-GO` 不是任务失败，而是有效的质量结论。修复后生成新的 RC 重新验收。

## 16. 验收用例

| 编号 | 场景 | 通过条件 | 级别 |
|---|---|---|---|
| RC-01 | 候选版本冻结 | 版本、代码、依赖、数据和构建摘要唯一 | P0 |
| RC-02 | 无账号首次访问 | 直接开始使用，无登录阻断 | P0 |

## 19. 执行顺序

1. 将 M7-07 更新为 `[doing]`；
2. 审核 M7-01 至 M7-06 的状态和缺失证据；

## 21. 完成定义

M7-07 标记 `[done]` 必须同时满足：

- 发布候选版本、规则、数据、依赖、开关和构建摘要已冻结；
- M7-01 至 M7-06 必需证据完整且对应同一候选版本；
- 25 项发布用例有实际结果，不使用推测替代实测；
- 10 份匿名报告通过内容顾问复核；
- P0 为 0，不存在不可豁免 P1；
- 所有剩余风险有责任人、期限、降级和回滚条件；
- 回滚包可用且至少完成两类演练；
- 产品、技术、测试、内容、安全和发布负责人完成签字；
- 管理层给出明确 `GO` 或合规的 `CONDITIONAL GO`；
- 证据包不包含真实用户材料或秘密值；
- 任务清单已更新为“等待用户明确授权执行 M7-08”。

以下情况只能保持 `[review]`：技术验收完成但管理层尚未签字，或实机/内容顾问证据仍待补齐。

出现 P0、不可豁免 P1 或无法准备回滚时，应记录为 `NO-GO`；修复后生成新 RC 再次执行 M7-07，不能直接进入 M7-08。
