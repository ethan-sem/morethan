# M4-08 证据不足降级实施说明

> 完成日期：2026-08-13  
> 状态：已完成  
> 范围：画像证据缺口的追问、条件式建议与省略结论；不创建新事实、不调用模型

## 1. 完成结果

分析流程不再只用一句“信息不足”结束。目标保存后，系统会把最高优先级证据缺口转为最多三项可回答问题，或按照规则直接给出条件式建议、明确省略结论。

用户回答只选择报告如何降级，不会自动创建、修改或确认简历事实。

## 2. EvidenceDegradationPlan 1.0.0

每个降级项包含画像结论 ID、规则 ID、指标、规则配置动作、缺失原因、缺失证据类型、已有事实 ID、问题、答案、处理结果和展示文案。

处理结果固定为：

- `pending_question`：需要用户回答；
- `needs_fact_update`：用户表示有经历，但必须返回事实页补充和确认；
- `conditional_advice`：没有直接证据时按明确前提给建议；
- `omitted`：无法核实或规则要求省略，本次不输出能力判断。

根对象提供四种状态统计、规则集版本和非事实写入声明。结构采用关闭式校验，答案与处理结果必须逻辑一致。

## 3. 规则执行

降级器直接读取 `AnalysisRuleSet` 中的配置：

- `ask_user`：生成与指标对应的真实经历问题；
- `conditional_advice`：生成含适用前提和风险边界的建议；
- `omit_conclusion`：省略肯定或否定判断。

缺少必要证据与整体证据不足分别读取各自配置，不能把所有弱结论强行转成追问。每轮只处理排序最前的三项缺口。

## 4. 回答边界

- “有，尚未写清”：只显示返回事实页入口；事实未补充并确认前不升级结论；
- “目前没有”：不判断能力不足，转为选岗、准备或保守表述建议；
- “无法确认”：明确省略该判断；
- 回答保存在当前 React 内存，重新分析时按规则 ID带入；
- 事实或方向变化时旧降级结果失效；JD 内容变化只使 JD 对照、四层和行动结果失效，不清除已经回答的画像追问；
- 已省略结论不会继续生成对应 48 小时行动任务。

## 5. 页面实现

关键追问页现在由上下两部分组成：证据不足追问区和可选 JD 输入区。追问区显示待回答数、自动降级数、三个互斥答案和处理结果，并允许有证据的用户返回事实页。

报告增加证据边界模块，逐项显示“待回答、需补事实、条件式建议、已省略”。最大短板及第一优先动作也使用同一降级结果，避免页面不同区域口径冲突。
