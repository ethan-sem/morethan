# 纯前端 MVP 技术与数据方案

## 1. 技术约束

- 运行形态：静态 React/Vite 网站；
- 业务后端：无；
- 账号与数据库：无；
- 简历上传：不发生，只在浏览器读取；
- 默认智能能力：本地解析、规则引擎和静态知识包；
- MoreThan 模型密钥：绝不进入前端；
- 部署：复用官网静态发布方式。

## 2. 推荐前端模块

```text
src/career-copilot/
├─ pages/           流程页面
├─ components/      证据卡、步骤条、报告卡等
├─ parsers/         PDF、DOCX、纯文本解析
├─ extractors/      时间、数字、技能、经历结构提取
├─ rules/           表达、证据、JD、方向与行动规则
├─ knowledge/       岗位族和公司岗位静态 JSON
├─ report/          报告组装、复制、打印
├─ privacy/         PII 遮盖和清除
├─ storage/         明确受控的会话状态
└─ tests/           单元、样本与端到端测试
```

当前 `src/careerCopilot.jsx` 和 `src/career-copilot.css` 是 C1 骨架；进入 MVP 开发后逐步拆分，避免继续扩大单文件。

## 3. 文件解析

### 统一预检

- 单个文件硬上限为 10MB，超限时不读取正文、不加载格式解析库；
- 只接受 `.pdf`、`.docx`、`.txt`，同时校验扩展名与真实文件头，不单独信任浏览器 MIME；
- 空文件在解析前拦截；PDF 校验 `%PDF-`，DOCX 校验 ZIP 容器，TXT 拦截明显二进制伪装；
- 加密 Office 容器通过复合文档签名及 `EncryptedPackage`/`EncryptionInfo` 标识识别；
- 页面错误只展示固定错误码、用户可理解的说明和下一步动作，不输出底层异常或正文。

### PDF

- 使用浏览器兼容的 PDF 文本解析库；
- 只读取文本层，不上传文件；
- 对无文本层、加密、乱码和异常页数给出明确错误；
- 首版不把 OCR 作为上线依赖。

### DOCX

- 使用浏览器端 DOCX 文本抽取库；
- 忽略宏和嵌入对象；
- 不执行文档内脚本、链接或指令。

### 文本

- 支持直接粘贴；
- 保留段落和标题结构；
- 对过短、过长和明显非简历文本提示。

新增依赖前必须检查许可证、包体积、浏览器支持和维护状态。

## 4. 本地状态模型

| 数据 | 默认位置 | 生命周期 |
|---|---|---|
| 原始文件对象 | 内存 | 页面刷新/关闭即消失 |
| 原始简历文本 | 内存 | 页面刷新/关闭即消失 |
| 已确认结构化事实 | 内存；可选 sessionStorage | 本次标签页会话 |
| 目标与筛选条件 | sessionStorage | 本次标签页会话 |
| 报告 | 内存 | 导出后由用户自行保存 |
| UI 偏好 | localStorage | 用户手动清除前 |
| BYOK 密钥 | 仅内存 | 刷新、离开或分析完成后清除 |

禁止把原始文件、简历正文、联系方式、模型密钥写入 localStorage、URL、埋点或错误日志。

### 4.1 ResumeFacts v1 数据契约

当前结构版本为 `1.0.0`，由 `src/career-copilot/domain/resumeFacts.js` 定义。根对象包含：

- `document`：文档 ID、来源格式、非空白字符数和原文 UTF-16 长度；
- `facts`：教育、实习、项目、校园、技能、证书和成果事实；
- `privateFields`：只保存遮罩值和来源位置的敏感字段；
- `timelineFlags`：日期重叠、无效、缺失或冲突提示，不代表造假结论；
- `review`：整份事实确认进度；
- `createdAt`、`updatedAt`：UTC ISO 时间戳。

每条事实必须包含稳定 ID、分类、分类数据、来源引用、识别置信度、确认状态和来源类型。来源引用只记录文档 ID、字符起止位置、页码和章节，不复制原文片段。只有 `review.status = confirmed` 的事实能进入后续核心分析。

结构采用关闭式字段校验；新增字段或不兼容变化必须提升 `schemaVersion`，不能在 `1.0.0` 中静默扩展。

### 4.2 敏感字段识别与遮罩

当前使用 `src/career-copilot/privacy/piiDetector.js` 的纯函数在浏览器内识别姓名、手机/固定电话、邮箱、详细地址和身份证号。识别器版本为 `1.0.0`，输出直接兼容 `ResumeFacts.privateFields`：只包含稳定 ID、字段类型、遮罩值、UTF-16 来源区间、置信度和处理状态，不包含原值。

- 邮箱、电话和通过出生日期/校验位验证的身份证号采用确定性格式规则；
- 姓名优先要求显式标签，无标签页眉姓名只有在附近出现联系方式时才以中置信度识别；
- 地址要求显式地址标签和足够的详细地址信号，单独的目标城市不遮罩；
- 多规则命中同一区间时按地址、身份证号、邮箱、电话、姓名顺序消解，避免重复替换；
- `detected` 和 `confirmed` 默认遮罩，用户后续标记为 `dismissed` 时恢复显示；
- 页面状态仍只在内存保存解析正文；预览按来源区间即时生成脱敏副本，不把正文或联系方式写入 Web Storage、URL、日志或 `ResumeFacts`。

当前解析完成预览已经接入默认遮罩。M6 报告复制与打印必须复用同一遮罩函数，不得自行拼接未脱敏正文。

### 4.3 本地事实与时间线提取

当前使用三个版本均为 `1.0.0` 的确定性规则模块：章节规则、日期规则和 `ResumeFacts` 提取器。规则覆盖教育、实习、项目、校园、技能、证书和成果/奖项七类事实。

- 先识别中英文章节标题；无标题材料只在出现学校、公司、项目、技能等强信号时低置信推断；
- 章节内通过空行、日期和组织/岗位头部信号切分多条经历；
- 日期统一为年、月或日精度，支持点号、斜线、连字符、中文年月和“至今”；
- 每条事实都带稳定 ID、原文 UTF-16 区间、章节、可用时的 PDF 页码、0–1 置信分和固定原因码；
- 规则输出一律为 `review.status = pending`，在 M3-04 用户确认前不会进入核心分析；
- 敏感字段区间在写入普通事实数据前先替换为遮罩值，联系方式原值不会进入 `facts`；
- 时间线生成 `date_missing`、`date_invalid`、`date_conflict` 和 `date_overlap` 四类 `open` 提示；重叠只比较教育内部或实习内部，不把项目与实习并行误判为异常；
- 提取器不在根对象保存正文，只保存经过结构化的事实值和来源区间。

规则计算默认运行在独立 Web Worker，15 秒超时后终止；缺少 Worker API 时才动态加载纯函数在本地降级。材料页展示事实数量和时间提示数量，具体增删改、确认与排除交互由 M3-04 实现。

### 4.4 事实确认与分析准入

事实确认页直接读写当前页面内存中的同一个 `ResumeFacts` 对象，不建立第二套展示数据，也不写入 Web Storage。

- `confirmed`：用户明确确认，可由 `selectConfirmedFacts()` 进入后续分析；
- `pending`：新提取、新增或修改后的事实，不进入分析；
- `excluded`：用户选择不参与分析，可恢复为待确认；
- `uncertain`：用户选择“无法确认”，视为已处理但不进入分析；可恢复为 `pending` 后重新判断。

用户可以修改所有七类事实的核心字段、日期、动作、方法、结果、指标和工具；日期必须能规范为年、年月或完整日期。修改事实会把来源类型改为 `user_edited` 并重置为 `pending`。新增事实使用稳定的 `fact-user-{category}-{index}` ID、`user_added` 来源类型和空原文来源，不伪造简历区间。

删除事实时同步移除引用该事实的时间线提示，并从技能证据 ID 中清除悬空引用。所有操作后都重新运行 `ResumeFacts 1.0.0` 关闭式校验。

完成整份确认必须同时满足：不存在 `pending` 事实，且至少有一条 `confirmed` 事实。完成后根状态为 `completed` 并记录 UTC 时间；任何后续编辑、增删或状态变化都会重新打开为 `in_progress`。页面路由不能绕过该门槛，材料未成功解析时也不能进入事实页。

原文证据根据 `sourceRefs` 从仍在内存中的正文即时截取，并在展示前重新应用敏感字段遮罩。用户新增事实明确显示“无原文来源”，不把用户输入伪装成提取证据。

### 4.5 低置信、缺失证据与时间线处理

`src/career-copilot/domain/factReviewGuidance.js` 提供版本为 `1.0.0` 的纯前端核实引导。它只读取已有事实的分类、置信度、原因码和字段完整度，输出提示文案与建议补充字段，不向 `ResumeFacts` 写入推断值。

- 低置信事实明确提示“请勿直接当作已证实履历”；
- 中置信或关键信息不完整的事实显示分类化补充建议，例如组织、角色、日期、行动和结果；
- 规则原因码转换为用户可理解的核实原因，但不把团队结果等同于个人贡献、不把工具提及等同于熟练掌握、不把提名等同于获奖；
- 用户可将事实标记为 `uncertain`，该状态会解除整份确认的待处理阻塞，但 `selectConfirmedFacts()` 始终排除它；
- 时间线提示可独立标记为 `confirmed`（确认需注意）或 `dismissed`（不适用），不会自动确认、排除或改写关联事实；
- 整份事实确认的完成条件仍只取决于没有 `pending` 事实且至少存在一条 `confirmed` 事实，时间线提示作为核实辅助，不阻塞继续。

## 5. 解析与规则管线

```text
File/Text
  ↓ 类型和大小检查
文本解析
  ↓
PII 本地识别与遮盖
  ↓
段落/标题/时间线识别
  ↓
经历与证据抽取
  ↓ 用户确认
岗位规则 + JD 规则 + 公司静态知识
  ↓
结论对象
  ↓ 确定性模板
报告页面 / 复制 / 打印
```

结论对象至少包含：`type`、`claim`、`evidenceIds`、`ruleId`、`confidence`、`impact`、`nextAction`。

## 6. 本地规则引擎

规则采用可测试的纯函数，不依赖模型随机输出：

- 经历结构规则；
- 动作动词与空泛词规则；
- 数字、百分比、规模和结果规则；
- 个人贡献与团队贡献区分；
- JD 必要词和加分词覆盖；
- 岗位族证据映射；
- 公司岗位四层组合规则；
- 问题影响 × 可改善性 × 紧迫度排序；
- 行动模板选择。

规则不能仅返回分数，必须返回触发原因和证据。

### 6.1 AnalysisRuleSet v1 数据契约

`src/career-copilot/domain/analysisRules.js` 定义 `AnalysisRuleSet 1.0.0`。默认规则集版本为 `2026.08.1`，只覆盖实习和校招，首版包含动作、方法、结果、规模、个人贡献、岗位相关性和可信度七项通用指标。

每条规则必须包含：

- 稳定 ID、指标代码、名称和用途说明；
- 必要证据和辅助证据引用；
- 0–1 权重，整组规则权重之和必须为 1；
- `strong > adequate > weak` 的有序阈值；
- 优势、问题、信息不足和通用边界四类解释；
- 最小已确认事实数、最小证据数、信息不足动作、必要证据缺失动作和置信度上限。

证据目录固定为 `E-ACTION`、`E-METHOD`、`E-RESULT`、`E-SCALE`、`E-OWNERSHIP`、`E-RELEVANCE` 和 `E-CREDIBILITY`。规则只能引用目录中已声明的证据类型，实际分析只能从 `selectConfirmedFacts()` 返回的事实中构造证据。

降级动作只能是：继续追问、给出条件式建议或省略结论。契约明确要求内部聚合结果不得作为单一求职竞争力总分展示；报告仍限制最多 3 项优势、3 项问题和 5 项行动。

契约采用关闭式校验：未知版本、未知字段、重复 ID、悬空证据引用、未归一化权重、错误阈值顺序或缺失降级策略均会返回稳定错误码，不能静默进入分析。

### 6.2 方向画像与经历证据匹配

`src/career-copilot/domain/careerProfileAnalysis.js` 实现版本为 `1.0.0` 的确定性画像分析。岗位画像版本为 `1.0.0`，覆盖产品经理、产品/用户运营、市场/品牌/增长、软件研发、数据分析/商业分析和金融/财会通用六类首发方向。

- 输入首先通过 `ResumeFacts` 校验，再调用 `selectConfirmedFacts()`，其他状态事实不会进入方向或证据计算；
- 用户可明确指定方向，也可选择“请先帮我判断”，后者按已确认事实中的任务词和技能词选择当前证据覆盖最强的方向；
- 事实字段映射为 M4-01 的七类证据，每条证据保存事实 ID 和命中字段路径；
- 规则输出优势、简历证据短板或信息不足，并保存规则 ID、证据 ID、事实 ID、置信度、内部得分、边界说明和下一动作；
- 内部得分只用于排序与阈值判断，不展示为求职竞争力总分；
- 没有已确认事实时不产生优势或短板，全部降级为信息不足；
- 报告最多展示 3 项优势和 3 项问题，短板文案明确不等同于真实能力不足。

目标设置与分析结果只保存在当前 React 页面内存。当前真实流程已用该分析替换固定示例判断；从首页单独打开的示例报告仍明确标注为示例，避免与个性化分析混淆。

### 6.3 JdProfile v1 与本地文本提取

`src/career-copilot/domain/jdExtractor.js` 定义并生成 `JdProfile 1.0.0`，提取器版本为 `1.0.0`。输入只接受 20–30,000 字的粘贴文本，统一换行与列表符号后按中英文标题和行级信号分类。

结构包含：

- `responsibilities`：岗位职责；
- `requirements.required`：硬要求；
- `requirements.preferred`：加分项；
- `keywords.task/skill/threshold`：任务词、技能词和门槛词；
- `riskItems`：歧视性表达、费用要求、高敏信息要求、模糊薪酬和过强工作边界五类待核实提示；
- `coverage`：三个主要区块是否识别到内容；
- 结构版本、提取器版本、字符数、行数和生成时间。

每个职责、要求和风险项只保存清洗后的单行内容、命中词及原始行号，不复制完整 JD 原文。原文只在当前 React 内存中的输入状态存在，不写入 `JdProfile`、sessionStorage、localStorage、URL、日志或网络请求。

风险提示只用于提醒用户通过招聘方官方渠道进一步核实，不作违法、诈骗或歧视的确定性法律结论。没有 JD 时页面允许直接跳过并继续使用通用岗位族规则；本任务仅结构化 JD，不在 M4-03 内比较简历差距。

`validateJdProfile()` 采用关闭式校验，拒绝未知版本、未知字段、无效条目、无效来源行号和不支持的风险类型。

### 6.4 JdGapAnalysis v1 差距比较

`src/career-copilot/domain/jdGapAnalysis.js` 定义 `JdGapAnalysis 1.0.0`。比较器接收有效 `ResumeFacts` 和 `JdProfile`，对每条职责、硬要求和加分项生成独立结果：

- `covered`：已确认事实中存在直接相关证据；
- `partial`：存在部分或仅技能清单层面的相关表达，但不足以完整覆盖；
- `not_found`：当前已确认简历事实中未找到可直接引用的相关证据。

每项结果保留 JD 条目 ID、类型、清洗文本、原始行号、状态、内部匹配值、命中/缺失关键词、事实 ID、命中字段路径、解释和下一动作。汇总只显示条目总数和三种状态数量，以及未找到证据的硬要求数量。

比较器只从 `selectConfirmedFacts()` 读取事实。技能名称或关键词单独命中时，证据质量上限为 0.55；只有实习、项目等事实中的动作、方法、工具或结果命中才能作为直接相关证据。`年`、`天`、`实习`、`经验`、`学历`等过于宽泛的词不单独作为匹配依据。

关闭式输出结构不允许加入录取概率、单一竞争力总分或保证字段。页面始终说明“未找到证据”不等于“不具备能力”；无 JD 时不生成或展示对比结果。

### 6.5 ApplicationTierPlan v1 四层投递组合

`src/career-copilot/domain/applicationTierPlan.js` 定义 `ApplicationTierPlan 1.0.0`。输入为有效的方向画像，以及可选的同一简历文档 JD 差距结果；输出固定包含冲刺、主申、稳妥、探索四条策略泳道。

每条泳道包含状态、目标岗位族、建议投递占比、理由、启用条件、证据事实 ID 和风险说明。四条占比之和必须为 100%，只代表有限投递资源的组合建议，不是成功概率或岗位质量评分。

- 冲刺：围绕当前方向中竞争更强但任务相邻的岗位，小比例验证；
- 主申：围绕当前证据最匹配的方向，作为主要投递资源；
- 稳妥：必须结合具体 JD，只有大部分条目有直接/部分证据且无未覆盖硬要求时才为 `active`，否则为条件式建议；
- 探索：使用相邻且有少量证据的方向收集真实市场反馈，没有相邻证据时仅作小范围验证。

没有 JD 时，主申层要求先收集 3–5 份同类 JD，稳妥层保持条件式。没有已确认事实时全部投递资源暂放探索层，不生成虚假的主方向确定性。

当前结构不包含公司 ID、公司排名、在招状态或永久层级。M5 静态知识库完成后，具体“公司 × 岗位族 × 地点 × 招聘类型”记录才能在审核来源和时效约束下映射到这些策略泳道。

### 6.6 ActionPlan v1 三时间窗行动计划

`src/career-copilot/domain/actionPlan.js` 定义 `ActionPlan 1.0.0`。它只接收同一轮有效的方向画像、可选 JD 差距和四层投递策略，在浏览器内确定性生成 3–5 项任务，并强制覆盖 `48_hours`、`7_days`、`30_days` 三个时间窗。

每项任务包含稳定 ID、时间窗、优先级、触发规则、触发对象、标题、理由、步骤、产出物、完成标准、预计分钟数和证据事实 ID。根对象记录上游三个契约版本、文档 ID、分时间窗数量、预计总用时和非保证声明。结构采用关闭式校验，不接受截止日期、云同步、概率或保证字段等静默扩展。

生成优先级依次为：未覆盖硬要求、证据较弱/未覆盖的岗位职责、画像关键证据缺口、岗位证据矩阵、首批十岗投递组合、30 天真实反馈复盘。没有 JD 时，48 小时窗口固定加入“收集 3–5 份带来源真实 JD”，不能假装已完成具体岗位匹配。

行动计划随简历事实、方向、JD 或四层策略变化而失效并重新生成。用户勾选完成只改变 React 页面内存，不写入 localStorage、sessionStorage、IndexedDB，也不提供跨设备或刷新恢复。

### 6.7 ConclusionProvenance v1 结论来源索引

`src/career-copilot/domain/conclusionProvenance.js` 定义 `ConclusionProvenance 1.0.0`。它不修改 M4-02 至 M4-06 的稳定数据契约，而是为画像结论、JD 差距、四层泳道和行动任务建立独立来源索引。

每项来源记录包含目标类型、目标 ID、来源类型、事实 ID、规则 ID、公开来源及解释。来源类型固定为：

- `confirmed_fact`：结论直接引用用户已确认事实；
- `rule_inference`：浏览器本地规则依据已有输入形成的判断；
- `public_source`：有 HTTPS 来源 URL、来源标题和合法核验日期的公开资料。

每项结论都必须包含 `rule_inference`；只有 `factIds` 非空时才允许 `confirmed_fact`；只有公开来源数组非空且通过关闭式校验时才允许 `public_source`。公开资料绑定的目标必须真实存在，重复绑定、HTTP 链接、无效日期和未知字段都会失败。当前 M5 尚未提供审核知识包，因此真实页面只显示前两类，不生成虚假“公开资料”标签。

### 6.8 EvidenceDegradationPlan v1 证据不足降级

`src/career-copilot/domain/evidenceDegradation.js` 定义 `EvidenceDegradationPlan 1.0.0`。它读取画像中的短板与信息不足结论，并严格执行 `AnalysisRuleSet` 为每条规则配置的 `ask_user`、`conditional_advice` 或 `omit_conclusion`。

每轮最多处理三项高优先级缺口。缺少必要证据且配置为追问时，生成一个可由用户选择“有，尚未写清 / 目前没有 / 无法确认”的问题：

- 有，尚未写清：状态变为 `needs_fact_update`，只能返回事实页补充真实内容并重新确认；
- 目前没有：状态变为 `conditional_advice`，显示包含适用前提和禁止事项的建议；
- 无法确认：状态变为 `omitted`，本次不对该项能力作肯定或否定判断。

整体信息不足时执行规则配置的条件式建议；配置为省略时直接隐藏肯定判断。所有答案和降级状态只驻留当前页面内存，不写入 `ResumeFacts`。行动计划会读取降级结果，已省略的画像结论不能继续成为行动触发器。

## 7. 静态知识包

建议文件：

```text
public/data/career-copilot/
├─ manifest.json
├─ role-families.json
├─ skill-aliases.json
├─ source-whitelist.json
├─ company-role-pool.json
└─ action-templates.json
```

`manifest.json` 记录版本、发布日期、来源数量、核验截止日期和校验哈希。网站加载失败时仍可完成简历结构诊断，只隐藏公司岗位分层并说明原因。

M5-02 已增加 `SourceWhitelist 1.0.0` 与 `source-whitelist.json`。白名单按精确 HTTPS hostname 匹配，记录发布主体、身份核验页、访问方式、可支持的事实类型、人工复核周期和限制条件。当前全局策略为 `link_only + manual_review_only`：白名单不是抓取许可，不允许浏览器或构建脚本批量采集第三方页面，也不允许绕过登录、验证码或访问控制。

企业官方招聘源可以成为实时岗位状态的证据，但来源首页本身仍不够；只有人工打开并核验的岗位级页面才能支持 `open`。政府和高校来源可用于公共信息、招聘线索和交叉核验，不能单独证明第三方企业岗位仍在招。

## 8. 公司岗位时效

- 静态记录必须包含 `sourceUrl` 和 `verifiedAt`；
- 页面根据 `expiresAt` 决定显示“已核验”或“需要官网确认”；
- 过期记录不删除历史来源，但不得显示为确定在招；
- 更新由顾问/运营修改 JSON、运行校验脚本、重新构建发布；
- 不在浏览器中抓取第三方招聘网站。

## 9. BYOK 实验模式

纯前端无法安全保存 MoreThan 的统一模型密钥。P1 可以提供用户自备密钥：

1. 用户主动开启实验模式；
2. 选择模型供应商并输入自己的密钥；
3. 界面展示发送字段和供应商隐私提示；
4. 密钥与请求只存在当前页面内存；
5. 调用后立即清除可清除的引用；
6. 供应商 CORS 或安全策略不允许时终止，不使用公共代理绕过；
7. 本地规则分析始终保留。

P1 开发前仍需要重新审核供应商官方浏览器调用政策，不承诺所有模型可用。

## 10. 安全控制

- 文件类型白名单、大小限制和解析超时；
- 不执行文件中的 HTML、脚本、宏或提示词；
- 第三方库启用依赖审计；
- 严格 CSP，默认禁止未知网络请求；
- 错误日志只记录错误码和模块，不记录正文；
- 统计工具屏蔽输入框、textarea 和文件名；
- 一键清除内存与 Web Storage；
- 导出默认脱敏；
- 不缓存包含简历正文的页面快照。

## 11. 性能预算

- 初始 JS gzip 建议 ≤ 180KB；解析库尽量动态加载；
- 知识包首屏不加载，进入公司分层前再加载；
- 单个静态知识包建议 ≤ 2MB 压缩前；
- 解析和规则计算放入 Web Worker，避免阻塞 UI；
- PDF、DOCX、TXT 使用按格式拆分的独立 Worker；二进制通过 transferable `ArrayBuffer` 转移所有权，任务成功、失败、取消或 45 秒超时后立即终止线程；
- 大文件超限时直接提示，不在低性能手机上强行处理。

## 12. 从 MVP 迁移到长远版

迁移时保留：解析器、规则引擎、知识 Schema、报告 Schema 和 UI 组件。替换：

- 本地会话 → 服务端用户档案；
- 静态知识包 → 版本化数据库；
- 本地规则 → 规则 + 服务端模型；
- 本地导出 → 云端报告历史；
- 手动知识更新 → 数据适配器和运营后台。
