# M6-06 透明度与使用边界实施说明

> 状态：已实施  
> 范围：纯前端 MVP；实习 / 校招；无账号、后端或模型 API

## 1. 目标

让用户在提交材料前和查看、复制、打印报告时，始终能准确理解四件事：内容如何生成、材料如何处理、结论不能代表什么、公开资料何时需要重新核验。

## 2. 统一披露口径

### 2.1 生成方式

- 统一标识为“本地规则生成（非生成式 AI）”；
- 报告由浏览器内确定性规则处理用户已确认事实、所选方向及可选 JD；
- 当前版本不调用生成式 AI，不把简历发送给模型服务；
- 不使用含混的“AI 已分析”措辞，避免用户误解网络上传或模型推断。

### 2.2 隐私与保存

- 原始文件、简历正文、JD 和诊断报告默认只驻留当前页面内存；
- 仅非敏感流程位置可以写入本次会话的 `sessionStorage`；
- 不自动保存，不提供账号档案或云端历史；
- 页面关闭或刷新前提示用户先复制脱敏文本或保存 PDF。

### 2.3 结果边界

- 只供实习与校招规划参考；
- 不代表招聘方评价或用户真实能力上限；
- 不输出、暗示或保证录用概率、面试邀请、录用结果或 offer；
- 用户仍需最终核对事实、简历表述和申请材料。

### 2.4 信息时效

- 公司资料区分“复核期内”“待自行核实”“本次未使用”三种状态；
- 显示本次查看日期，具体公司卡继续显示逐条来源、核验日期和有效期；
- “复核期内”不等于岗位仍在招聘；
- 超过复核期限后仅保留官方入口供核对，申请前一律以招聘方官方页面为准。

## 3. 展示位置

1. 开始页：规则生成建议、不构成录用保证、简历仅本地处理。
2. 材料页：提交前隐私卡明确不自动保存及不调用生成式 AI。
3. 生成页：明确使用浏览器本地规则且不上传简历。
4. 报告页：四块结构化透明度声明及声明版本。
5. 复制文本 / 打印 PDF：保留同一套生成、隐私、结果及时效说明。

## 4. 工程约束

- `reportDisclosure.js` 是网页和导出报告的唯一统一披露源；
- 披露对象使用版本 `1.0.0`，便于未来口径升级与测试；
- 测试覆盖非生成式 AI、本地内存、非录用保证及三类资料时效状态；
- M6-05 隐私构建门禁继续阻止默认网络发送和敏感持久化。

## 5. 验收标准

- 用户无需展开隐藏条款即可在报告页看到四类边界；
- 页面、复制文本和打印版口径一致；
- 不把“本地规则”宣传成生成式 AI；
- 公司资料不会被表述为实时岗位或永久有效；
- 自动化测试、类型检查、lint、隐私/数据门禁及生产构建全部通过。
