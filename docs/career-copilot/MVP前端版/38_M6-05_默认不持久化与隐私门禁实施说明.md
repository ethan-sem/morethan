# M6-05 默认不持久化与隐私门禁实施说明

## 1. 完成范围

M6-05 将“默认不保存简历和报告”从页面文案升级为可执行策略、运行时审计和构建门禁。

当前求职助手只允许一个持久化条目：

- 存储位置：`sessionStorage`；
- 键名：`morethan-career-copilot-flow-v1`；
- 字段：版本号、当前步骤、已访问步骤；
- 生命周期：当前浏览会话；
- 用途：避免用户返回上一步时流程导航失效。

除此之外，localStorage、IndexedDB、Cache Storage 和 Cookie 的求职助手持久化白名单均为空。

## 2. 默认仅存内存的数据

以下内容只存在于 React 状态、普通 JavaScript 对象、Worker 内存或当前文件事件中：

- 原始简历文件和文件名；
- 简历提取文本；
- 姓名、电话、邮箱、地址等敏感字段识别结果；
- `ResumeFacts` 结构化事实；
- 求职方向、JD 原文和 JD 结构；
- 画像分析、优势短板、差距、四层建议和公司目标池；
- 行动计划、完成状态和证据来源索引；
- 复制用的脱敏报告文本。

刷新或关闭页面不会恢复这些内容。

## 3. 持久化白名单

`persistencePolicy.js` 统一定义允许的浏览器存储面和字段。流程状态写入前必须通过关闭式校验：

- 未知存储区域拒绝；
- 非白名单键拒绝；
- 流程对象出现未知字段拒绝；
- 非法步骤、版本和访问列表拒绝；
- localStorage、IndexedDB、Cache Storage 和 Cookie 均无可写条目。

因此不能通过把完整应用状态传给现有存储函数来绕过限制。

## 4. 运行时隐私审计

运行时审计器可以检查：

- sessionStorage 与 localStorage 的求职助手键及载荷；
- URL 中是否出现当前会话敏感值；
- 求职助手 Cookie；
- 求职助手 Cache Storage 名称；
- 求职助手 IndexedDB 名称。

审计结果只返回存储面、键名和错误码，不回显命中的手机号、邮箱、简历文本或报告正文。

## 5. 构建期隐私门禁

新增 `validate:privacy`，并纳入统一 `check`。它会扫描求职助手生产源码，阻断：

- 新增 `fetch`、XHR、WebSocket、EventSource 或 `sendBeacon`；
- 将业务状态写入 URL 查询参数或 Hash；
- 在白名单模块外写 localStorage/sessionStorage；
- 新增 IndexedDB、Cache Storage 或 Cookie 写入；
- 直接序列化简历、事实、JD、报告、行动计划或 API Key。

M6-04 的清理模块属于删除路径，不被误判为持久化写入。

## 6. 离开提醒

页面存在简历、JD、分析或行动计划且尚未导出时：

- 官网顶部导航、助手退出和 Hash 前进/后退统一触发站内离开确认；取消后保持当前助手会话；

- 页面右下角持续提示“本次内容不会自动保存”；
- 刷新或关闭页面触发浏览器原生离开确认；
- 成功复制脱敏报告或打开打印保存流程后，当前提醒解除；
- 用户重新修改简历、事实或 JD 后，提醒重新启用。

浏览器出于安全原因会自行决定离开确认的最终文案，网页不能强制显示自定义文本。

## 7. 审计结论

本次源码审计确认：

- 默认流程没有简历或报告网络请求；
- 没有简历内容、JD、报告、联系方式写入浏览器持久化介质；
- 没有将敏感状态写入 URL；
- 没有生产环境简历正文控制台日志；
- 唯一的 sessionStorage 写入仅包含经过白名单校验的流程导航状态。

## 8. 验收要点

- 完成完整分析后，浏览器存储中只有非敏感流程位置；
- 刷新页面不能恢复简历、事实、JD 或报告；
- 敏感内容不出现在 URL、Cookie、Cache Storage 或 IndexedDB；
- 未导出时有明显提醒及浏览器离开确认；
- 导出后可解除提醒，修改材料后再次启用；
- 新增敏感持久化或默认网络发送时，统一检查失败。
