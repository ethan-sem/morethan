# M2-03 DOCX 浏览器本地解析实施说明

> 完成日期：2026-08-09  
> 状态：已实现并通过自动测试与生产构建  
> 解析范围：标准 `.docx` 文本文档；不支持旧版 `.doc` 或含宏 `.docm`

## 1. 已实现能力

- 用户选择 DOCX 后，在浏览器内将 `File` 转为独立 `ArrayBuffer`；
- 按需加载 `mammoth@1.12.0` 的浏览器适配版本；
- 只调用 `extractRawText({ arrayBuffer })`，提取正文、段落及表格中的文字；
- 统一换行符、不换行空格和多余空行，保留段落边界；
- 返回全文、非空白字符数、文本段落数和脱敏后的解析提示；
- 页面与 PDF 共用本地解析进度、成功预览、错误及重新选择状态；
- 重新选择、重置或离开组件时停止接收旧任务结果；
- 文件与提取文本只存在于 React 内存状态，不写入浏览器持久化存储。

## 2. 结果结构

```text
DocxParseResult
├─ text              规范化后的全文
├─ characterCount    非空白字符数
├─ paragraphCount    以段落空行统计的文本段数
└─ warnings[]        只包含固定错误码和级别
```

M3 事实提取将直接使用 `text`。原始 DOCX、图片、样式和内部 XML 不进入后续流程。

## 3. 安全边界

- 不调用 Mammoth 的 `convertToHtml` 或 `convertToMarkdown`；
- 不把 DOCX 内容转换为 HTML，也不会向 DOM 注入文档内容；
- 不执行 VBA 宏、脚本、OLE 对象、嵌入文件或外部链接；
- 不读取图片二进制，也不生成图片对象 URL；
- Mammoth 的外部文件访问保持默认关闭，不提供开启入口；
- 解析器只接收本地 `Blob`、`ArrayBuffer` 或 `Uint8Array`，不接受远程 URL；
- Mammoth 原始提示文字不会进入 UI 或日志，只映射为固定 `warning/error` 代码。

文件大小、`.docm`/伪装扩展名和加密/损坏错误已由 M2-05 加入；独立 Worker、取消和统一超时已由 M2-06 完成。本功能仍属于 MVP 开发状态。

## 4. 当前错误码

| 错误码 | 用户结果 |
|---|---|
| `DOCX_NO_TEXT` | 没有检测到足够正文 |
| `DOCX_INVALID` | ZIP 或 DOCX 结构损坏/不标准 |
| `DOCX_EMPTY_FILE` | 空文件 |
| `DOCX_ABORTED` | 已停止旧解析任务 |
| `DOCX_PARSE_FAILED` | 解析失败，建议重新导出或改用 PDF |
| `DOCX_UNSUPPORTED_INPUT` | 不是本地二进制输入 |

M2-05 已统一 PDF、DOCX、TXT 的文件校验和错误文案。

## 5. 验证方法

自动测试在内存中构建了一个包含以下组成的最小标准 DOCX：

- `[Content_Types].xml`；
- Office Document 主关系；
- `word/document.xml`；
- 中英文简历段落。

该虚构文件通过真实 Mammoth 浏览器包完成了解压和文本抽取，没有将任何真实简历加入仓库。

## 6. 验证结果

- 真实 Mammoth 浏览器运行时 DOCX 抽取：通过；
- 换行与段落规范化：通过；
- 无正文、损坏 ZIP、解析警告脱敏：通过；
- 页面 DOCX 成功预览：通过；
- PDF 回归：通过；
- 8 个测试文件、26 项测试全部通过；
- ESLint 与严格类型检查通过；
- 解析依赖探针构建通过；
- 官网生产构建通过。

生产构建中：主 JS 为 84.99 kB gzip，仍低于 180 kB 预算；Mammoth 作为 125.39 kB gzip 的动态块，仅在用户选择 DOCX 时加载；PDF 依赖仍保持独立按需加载。
