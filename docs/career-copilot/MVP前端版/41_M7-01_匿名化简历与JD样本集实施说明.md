# M7-01 匿名化简历与 JD 样本集实施说明

> 状态：已实施  
> 数据集：`morethan-career-copilot-synthetic-v1`  
> 原则：只使用人工编写的纯虚构材料，不以真实简历脱敏后入库

## 1. 目标

建立可重复、可验证、不可回溯真实个人的质量测试基线，覆盖求职助手首发实习/校招流程中的正常输入、信息不足、语言差异、时间异常、隐私字段和岗位匹配边界。

## 2. 样本构成

### 2.1 简历样本：10 份

| ID | 场景 | 主要用途 |
|---|---|---|
| resume-empty | 空白输入 | 验证空状态与无事实降级 |
| resume-stem-two-internships | 理工科、两段相关实习 | 验证多经历、方法和量化结果 |
| resume-business-no-metrics | 商科、项目多但缺量化 | 验证证据短板而非能力否定 |
| resume-cross-major-product | 跨专业转产品 | 验证以项目证据而非专业名称判断 |
| resume-early-student | 低年级、经历少 | 验证信息不足和成长型行动建议 |
| resume-timeline-conflict | 时间重叠、倒序、缺失 | 验证三类时间线待核实提示 |
| resume-english-data | 英文简历 | 验证英文标题和经历识别 |
| resume-bilingual-operations | 中英混合简历 | 验证双语材料稳定性 |
| resume-dense-contacts-table | 联系方式密集、表格式 | 验证敏感字段识别与非段落排版 |
| resume-unheaded-minimal | 无标题、内容极少 | 验证推断章节与低置信降级 |

### 2.2 JD 样本：6 份

| ID | 场景 | 主要用途 |
|---|---|---|
| jd-product-high-match | 产品岗高匹配 | 验证职责、硬要求和加分项 |
| jd-quant-low-match | 量化岗明显低匹配 | 验证“简历未找到证据”边界 |
| jd-frontend-english | 英文前端 JD | 验证英文区块和技能词 |
| jd-operations-bilingual | 中英混合运营 JD | 验证双语岗位描述 |
| jd-risk-language | 性别、费用、银行卡措辞 | 验证三类谨慎核实提示 |
| jd-empty | 空白 JD | 验证可跳过和过短输入错误 |

合计覆盖 15 个去重测试场景。

## 3. 匿名与虚构规则

- 不采用“真实简历脱敏后入库”，避免遗漏隐含身份线索；
- 所有非空文本首行包含英文纯虚构标记；
- 学校、组织、项目和岗位使用明确虚构名称；
- 邮箱只允许保留测试域名，不允许常见真实顶级域名；
- 禁止身份证格式数字和“真实候选人/真实简历”标记；
- 联系方式样本只为测试识别器，不代表可联系个人；
- 样本目录不位于 `public/`，不会被复制进网站静态资源。

## 4. 机器可执行清单

`manifest.json` 对每份样本声明：

- 稳定 ID、类型、相对文件路径和语言；
- 一个或多个测试场景；
- 最少事实数、预期事实类别和时间线类型；或
- JD 的最少职责、硬要求、加分项、风险类型和预期错误码。

任何未登记文件都不能自动成为质量基线，任何重复 ID、重复文件、越界路径或未知字段都会被拒绝。

## 5. 构建门禁

`validate-career-fixtures.js` 在本地和生产构建中执行：

1. 校验清单版本、关闭式字段、ID、路径和数量；
2. 检查必测场景覆盖；
3. 扫描虚构标记、真实邮箱域名和身份证格式；
4. 调用现有敏感字段识别器；
5. 用现有简历提取器生成并校验 `ResumeFacts`；
6. 核对事实类别和时间线预期；
7. 用现有 JD 提取器生成并校验 `JdProfile`；
8. 核对职责、要求、加分项、风险和错误预期。

门禁失败时生产构建直接终止。

## 6. 范围边界

M7-01 建立文本语义样本集。扫描 PDF、加密 PDF、损坏 DOCX 和超限二进制属于 M7-02 自动化测试资产；届时应由程序生成完全无个人信息的文件，不使用真实材料改造。

## 7. 验收标准

- 至少覆盖空白、跨专业、经历少、时间冲突、中文、英文和中英混合；
- 至少包含高匹配和低匹配 JD；
- 样本不含真实用户材料；
- 清单及预期结果可由机器校验；
- 校验纳入生产构建；
- 全量自动化测试与生产构建通过。
